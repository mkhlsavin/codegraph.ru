Runtime-реестр MCP-инструментов

Runtime-generated MCP tool registry для docs-sync coverage и source-module traceability.

СправочникОбновлено: 2026-08-06

CodeGraph предоставляет компактный operator-callable MCP profile, сгенерированный из runtime registry. По текущему MCP Argument MECE audit default operator surface содержит 94 callable tools, 447 raw parameters и 57 effective agent-facing parameters. Owner role profiles могут открывать дополнительные governed lane tools, поэтому не каждый role-specific tool виден в default Codex/OpenCode discovery.

  • Full operator-callable MCP profile: 94 callable tools
  • Raw parameter count: 447
  • Effective agent-facing parameter count: 57
  • Removed/defaulted/derived parameter count: 390
  • MCP resource surfaces: 4 resources and 5 resource templates
  • MCP resource projections: 0 resource candidates

Для role-lane workflows используйте accountable owner profile и передавайте structured fields как native arrays/objects. Не передавайте legacy JSON-string variants для полей, которые в активной MCP schema типизированы как arrays или objects.

Governed PRD и handoff notes

  • codegraph_digital_employee_prd_delivery_start создаёт active task capsules и handoff только для реально участвующих lanes. Марина / AI Workforce Governance и Глеб / DevOps and SRE являются activity-triggered: без прямой работы или изменённой поверхности, требующей их lane, они остаются только в planning visibility и не получают synthetic handoff или financial row.
  • codegraph_digital_employee_handoff_accept принимает optional native object financial_control_budget. Используйте его только для реального late handoff, если child task не унаследовала reserved budget packet из offer/start metadata.
  • codegraph_employee_task_start не принимает financial_control_budget как отдельное top-level поле. Для прямого task start передавайте reserved/approved Ева packet внутри operation_request.financial_control_budget.
  • codegraph_digital_employee_prd_delivery_status поддерживает compact aliases summary и compact; оба возвращают closure-summary payload без unsupported_status_view.
  • codegraph_task_checklist_generate включает waiver_templates с точными typed fields для codegraph_task_pre_completion_gate_get.

Ниже инструменты сгруппированы по исходным модулям. Используйте эту страницу как быстрый контрактный справочник, а за подробным поведением обращайтесь к соответствующему исходному файлу и профильным руководствам.

Дополнительные runtime-инструменты

Эти инструменты входят в текущую authoritative MCP surface и напрямую используются новыми task-capsule, recall и dashboard-control сценариями:

  • codegraph_context_active_task возвращает текущую active task capsule, привязанную к сессии.
  • codegraph_task_context_attachment_rationale_get объясняет, почему текущая active task capsule привязана к сессии.
  • codegraph_task_context_recall_rationale_get объясняет текущий surfaced recall bundle для сессии.
  • codegraph_task_context_feedback_submit записывает положительную или отрицательную обратную связь по активному recall bundle.
  • codegraph_task_context_recall_dismiss скрывает текущий recall bundle или подавляет его по умолчанию.
  • codegraph_task_context_story_capsule_list выводит или синхронизирует user-story task capsules, полученные из USER_STORIES.md.
  • codegraph_task_context_next_task_get возвращает следующую наиболее приоритетную project-scoped задачу с explainability.
  • codegraph_quality_structural_test_rule_list выводит deterministic CPG structural rules для выбранного проекта.
  • codegraph_quality_structural_test_run запускает deterministic structural tests и возвращает pass/fail evidence.
  • codegraph_quality_structural_test_waive записывает governed waiver для одного structural-test rule.
