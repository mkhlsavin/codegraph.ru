Как работать с DASHA, CARA и VERA

Руководство разделяет общий способ работы с ролями и текущий учебный пример. Не переносите частные требования демонстрационного набора на будущие.

РуководстваОбновлено: 2026-08-23

Руководство разделяет общий способ работы с ролями и текущий учебный пример. Не переносите частные требования демонстрационного набора на будущие пользовательские сценарии.

Общий контракт ролей

До запуска сформулируйте проверяемый вопрос и соберите доступные источники:

  • для DASHA — проектные данные, качество которых нужно оценить;
  • для CARA — сведения, позволяющие связать стоимость, сроки, физические объёмы и объекты;
  • для VERA — статус выполнения и подтверждающие документы.

Формат и количество файлов могут отличаться. В отчёте всегда должны быть видны принятые входы, проверенные поверхности, ограничения, уровень уверенности и недостающие данные.

Интерактивный запуск в dashboard

Интерактивный режим нужен, когда нужно показать не только готовый отчёт, но и действия ролей в сессии: старт, продолжение, уточнение, передачу между DASHA, CARA и VERA, а также факт вызова headless Codex.

Из корня репозитория выполните:

$env:CODEGRAPH_PG_PASSWORD="1234"
python scripts/run_app_stack.py restart --local --with-mcp
python scripts/run_app_stack.py status --local --with-mcp

Откройте http://127.0.0.1:3100/dashboard/onboarding-research, войдите как admin / admin и выберите сценарий «Динамический анализ инвестиционного строительства». В поле «Сотрудница» выберите, кто начинает анализ: DASHA, CARA или VERA. Поле «Вопрос» автоматически получает стартовый запрос под выбранный сценарий и сотрудницу; если оператор вручную изменил текст, переключатели больше не затирают этот вопрос. Кнопка «Запустить» передаст в chat workflow два учебных файла из docs/development/requirements/employees/examples:

  • E110-0038-8000489814-ПП-01-СЗ-01_(КиСР).xlsm;
  • Часть графика Корпус классификации и Склад реагентов.pdf.

Во время запуска смотрите на блок «Ход запуска». Он меняет стадии от подготовки запроса до сборки отчёта, поэтому оператор видит, что dashboard ждёт активный workflow, а не завис на одной строке статуса. Если стадия долго не меняется, откройте детали выполнения и проверьте статус провайдера.

Для демонстрации headless Codex раскройте «Показать детали выполнения агента» после ответа. Покажите Провайдер, Статус провайдера, Thread провайдера и Токены. Если показан детерминированный fallback, значит demo workflow отработал без headless Codex; это пригодно для проверки контроля, но не для показа ИИ-ответа.

Основной ответ в dashboard форматируется как отчёт: итог, ключевые наблюдения и недостающие подтверждения. Полный технический текст остаётся в блоке «Исходный текст ответа» и нужен только для диагностики.

Для последовательного сценария запустите DASHA и затем используйте кнопку «Передать»: dashboard сначала передаст типизированный пакет доказательств CARA, затем VERA. Для точечного вопроса можно сразу выбрать CARA или VERA и нажать «Запустить» без предварительного шага DASHA.

Standalone HTML для текущего учебного примера

Из корня репозитория выполните:

python scripts/run_investment_construction_agents_e2e.py

Команда использует подготовленные XLSM и PDF без headless Codex и создаёт три локальных артефакта:

  • investment_construction_agents_e2e.html — минимальный интерфейс для демонстрации;
  • investment_construction_agents_e2e.md — текстовый отчёт;
  • investment_construction_agents_e2e.json — машинный отчёт с трассировкой.

По умолчанию артефакты находятся в .tmp/investment-construction-agents-e2e. HTML работает локально, не загружает внешние ресурсы и не показывает пути к исходным файлам.

Как провести демонстрацию

  1. Откройте HTML и назовите границу сценария: это учебный профиль XLSM + PDF, а не перечень обязательных входов продукта.
  2. Покажите DASHA и объясните, что сейчас она проверяет конкретную книгу Excel, а по смыслу отвечает за входной контроль проектных данных в целом.
  3. Покажите CARA: основной объект анализа — CAPEX at risk, а не механическая сверка двух файлов.
  4. Обратите внимание на ограничение физических объёмов: доступна связка «стоимость — объём — объект», но не полная связка по каждой работе.
  5. Завершите блоком VERA: процент в графике не подтверждает факт без актов, фактических объёмов и освоения бюджета.

Подробный тайминг и ожидаемые реплики приведены в отдельном демо-сценарии.

Как читать результаты

DASHA — Data Acceptance, Screening & Harmonization Agent

Сначала проверьте статус входного контракта, затем качество структуры и список пробелов. Высокая оценка означает готовность продолжить анализ в заявленных границах, но не доказывает правильность всех инженерных или коммерческих данных.

CARA — CAPEX At Risk Agent

Разделяйте четыре типа наблюдений:

  • кандидат в CAPEX-риск;
  • пробел данных;
  • конфликт сопоставления;
  • известное ограничение или коммерческое допущение.

Кандидат в риск требует проверки владельцем стоимости и сроков. Пробел данных требует дополнительного источника. Известное ограничение нельзя автоматически превращать в риск.

VERA — Verified Execution Reporting Agent

Смотрите не только на статус графика, но и на блок недостающих подтверждений. Если нет актов, фактических объёмов или освоения бюджета, VERA снижает уверенность и не подтверждает факт выполнения. Так роль не подменяет отсутствие доказательств предположением.

Если вход заблокирован

Не пытайтесь интерпретировать пустой или повреждённый файл как успешную проверку. Исправьте путь, тип, доступность или содержимое входа и повторите запуск. Блокировка одной роли не даёт основания усиливать выводы другой.

Что передать на ручную проверку

Передайте ответственному специалисту:

  • паспорт качества входа от DASHA;
  • кандидаты в CAPEX at risk и основания CARA;
  • список недостающих подтверждений VERA;
  • машинный JSON, если нужна локальная трассировка до источника.
