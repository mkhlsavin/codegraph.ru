Как работать с DASHA, CARA и VERA

Это руководство описывает поддерживаемый сценарий в уже развёрнутом экземпляре CodeGraph. Параметры установки, адрес сервера и способ входа получите у.

РуководстваОбновлено: 2026-08-24

Это руководство описывает поддерживаемый сценарий в уже развёрнутом экземпляре CodeGraph. Параметры установки, адрес сервера и способ входа получите у администратора вашей среды.

Запуск анализа

  1. Откройте /dashboard/onboarding-research.
  2. Выберите профиль investment_construction_dynamic.
  3. Выберите начальную роль: DASHA, CARA или VERA.
  4. Проверьте автоматически предложенный вопрос и при необходимости уточните его.
  5. Запустите анализ и дождитесь итогового ответа.

Для этого профиля интерфейс автоматически прикрепляет встроенную книгу с проектно-сметными данными и фрагмент графика. Страница работает с демонстрационным набором данных; загрузка собственных файлов непосредственно на этой странице не поддерживается. Поэтому результат описывает демонстрационный набор, а не данные вашего проекта.

Назначение ролей

  • DASHA — Data Acceptance, Screening & Harmonization Agent — проверяет качество и пригодность входных данных.
  • CARA — CAPEX At Risk Agent — выявляет кандидатов в CAPEX-риск и проблемы сопоставления.
  • VERA — Verified Execution Reporting Agent — проверяет, подтверждено ли фактическое выполнение доступными источниками.

Результаты помогают специалисту провести проверку. Профессиональное суждение и решения по бюджету, договору и приёмке фиксирует ответственный специалист.

Продолжение сессии

После первого ответа выберите нужное действие из доступных для сессии:

  • confirm_mapping — подтвердить предложенное сопоставление данных;
  • continue — продолжить текущий анализ;
  • clarify — запросить уточнение;
  • transfer — передать типизированные доказательства следующей роли;
  • cancel — остановить текущий процесс.

Набор кнопок зависит от состояния сессии. При передаче следующая роль получает typed_evidence_package, а не неподтверждённое резюме предыдущего ответа.

Как читать результат

Сначала проверьте метаданные выполнения:

  • completed — процесс завершил предусмотренные шаги;
  • partial — доступен неполный результат, который нужно читать вместе с ограничениями;
  • blocked — процесс не смог безопасно продолжить; причина указывается в ответе;
  • fallback — использован детерминированный резервный режим.

fallback сообщает о резервном режиме, а результат модельного провайдера помечается отдельным полем происхождения. Проверьте это поле, недостающие входы и список доказательств. В интерфейсе индикатор прогресса даёт обратную связь во время ожидания; авторитетными остаются итоговый статус, метаданные провайдера и пакет доказательств.

Затем оцените содержательную часть:

  • у DASHA — качество входа, область проверки и пробелы;
  • у CARA — основание каждого кандидата в риск, конфликты сопоставления и допущения;
  • у VERA — подтверждения факта и список отсутствующих документов.

Если результат заблокирован или неполон

  1. Прочитайте причину blocked или ограничения partial.
  2. Не усиливайте выводы одной роли результатом другой.
  3. Если доступно clarify, уточните вопрос; если требуется сопоставление, используйте confirm_mapping.
  4. При проблеме среды передайте администратору идентификатор сессии, итоговый статус и метаданные происхождения. Не включайте в обращение секреты или закрытые документы.

Повторный запуск оправдан после исправления входа или среды. Само повторение запроса не устраняет недостающие доказательства.

Проверяемые источники контракта

  • src/investment_construction_agents/pack.py — DASHA, CARA и VERA;
  • src/investment_construction_agents/dynamic_workflow.py — действия, статусы и typed_evidence_package;
  • src/api/services/core_services/chat_service.py — профиль investment_construction_dynamic, метаданные и резервный режим;
  • frontend/src/pages/OnboardingResearchChat.tsx — маршрут, элементы управления и встроенный демонстрационный вход.
