Сценарий демонстрации DASHA, CARA и VERA

Пятиминутный внутренний сценарий на текущем учебном наборе XLSM и PDF.

РуководстваОбновлено: 2026-08-08

Назначение

Это внутренний учебный пример. Он показывает работу ролей на текущем наборе данных и не является универсальным перечнем обязательных документов.

Текущий учебный пример

Текущий учебный пример
Вход Роль в демонстрации
E110-0038-8000489814-ПП-01-СЗ-01_(КиСР).xlsm Проектно-сметные данные, физические объёмы и объекты для текущих проверок DASHA и CARA
Часть графика Корпус классификации и Склад реагентов.pdf Плановые и заявленные статусы для текущих проверок CARA и VERA

Физические объёмы в XLSM есть, но детализация ограничена: можно проверить связку «стоимость — объём — объект», но не полную связку по каждой работе.

Оба файла находятся в docs/development/requirements/employees/examples. В этом профиле DASHA и CARA используют листы Реестр смет, Сводка затрат и ВФО-Техн.К; это частные условия учебного набора, а не обязательные листы для любого будущего входа.

Подготовка интерактивного dashboard-демо

  1. Убедитесь, что оба файла находятся в папке примеров и не открыты другим процессом.
  2. Из корня репозитория запустите локальный стек:
$env:CODEGRAPH_PG_PASSWORD="1234"
python scripts/run_app_stack.py restart --local --with-mcp
python scripts/run_app_stack.py status --local --with-mcp
  1. Откройте http://127.0.0.1:3100/dashboard/onboarding-research и войдите как admin / admin.
  2. В поле «Сценарий» выберите «Динамический анализ инвестиционного строительства».
  3. В поле «Сотрудница» выберите роль для первого интерактивного запуска:
  • DASHA — входной контроль данных;
  • CARA — риск капитальных затрат;
  • VERA — подтверждение выполнения.

  1. Проверьте поле «Вопрос»: dashboard подставляет стартовый запрос под выбранный сценарий и сотрудницу. Если оператор вручную изменил текст, дальнейшее переключение сценария или сотрудницы этот ручной вопрос не затирает.

  2. Оставьте подставленный демо-вопрос или задайте один из рабочих вопросов:

  • DASHA: проверь качество входных проектно-сметных данных.
  • CARA: найди CAPEX at risk по стоимости, срокам, объёмам и объектам.
  • VERA: можно ли подтвердить заявленный процент выполнения?
  1. Нажмите «Запустить». Dashboard сам передаст оба demo-файла в chat workflow. Пока идёт запуск, показывайте блок «Ход запуска»: он последовательно меняет стадии подготовки запроса, проверки источников, сбора доказательств, фонового Codex и сборки отчёта. Для последовательного показа используйте кнопку «Передать»: после DASHA она запускает CARA, после CARA — VERA. Для точечного показа выберите нужную сотрудницу и нажмите «Запустить» без прохождения всей цепочки.

После ответа сначала покажите структурированный отчёт: итог, ключевые наблюдения и список подтверждений, которые нужны сотруднице для перехода из candidate/blocked в verified. Сырой технический текст остаётся в раскрывающемся блоке «Исходный текст ответа». Затем раскройте «Показать детали выполнения агента». Для показа headless Codex нужны поля Провайдер: codex_subscription, Статус провайдера: completed, Thread провайдера и Токены. Если вместо этого виден режим детерминированный fallback, демонстрируйте это как контрольное поведение без headless Codex и проверьте доступность Codex SDK/runtime отдельно.

Подготовка standalone HTML-демо

Этот режим нужен для статичного пятиминутного показа без интерактивных действий и без headless Codex. Из корня репозитория выполните:

python scripts/run_investment_construction_agents_e2e.py

Откройте локальный файл .tmp/investment-construction-agents-e2e/investment_construction_agents_e2e.html.

Стоп-условия

Остановите демонстрацию и исправьте вход, если файл отсутствует или не читается, одна из ролей не сформировала отчёт, HTML не создался либо в результате появился вывод о подтверждённом факте без актов, фактических объёмов и освоения бюджета. Не публикуйте локальный каталог с JSON, Markdown или исходными файлами: этот сценарий предназначен только для внутреннего показа.

Пятиминутный маршрут в dashboard

0:00–0:40 — рамка

Покажите экран «Исследование проекта», выбранный строительный сценарий, поле «Сотрудница» и вопрос. Скажите: «Два файла — текущий тестовый набор, а не универсальное требование. В других сценариях роли могут получать другие проектные источники».

0:40–1:40 — DASHA

Выберите DASHA и запустите вопрос либо покажите результат текущего запуска. В деталях отметьте роль, typed evidence и provider status. Скажите: «Здесь DASHA работает с XLSM, но её назначение шире: входной контроль и гармонизация проектных данных».

1:40–3:10 — CARA

Нажмите «Передать» после DASHA или выберите CARA в поле «Сотрудница» и запустите вопрос напрямую. Покажите кандидаты риска капитальных затрат, конфликт общего ключа и ограничение физических объёмов. Скажите: «CARA ищет CAPEX at risk на пересечении стоимости, сроков, объёмов и объектов. Она не утверждает полную построчную сверку, которой источники не позволяют».

3:10–4:30 — VERA

Нажмите «Передать» после CARA или выберите VERA в поле «Сотрудница» и запустите вопрос напрямую. Покажите низкую уверенность доказательств и список недостающих подтверждений. Скажите: «Процент выполнения в графике — не подтверждённый факт. Без актов, фактических объёмов и данных об освоении бюджета VERA оставляет вывод ограниченным».

4:30–5:00 — итог

Подведите итог: DASHA определила качество входа, CARA сформировала вопросы по CAPEX at risk, VERA отделила заявленный статус от доказанного факта. Роли независимы, хотя запускаются одной workflow-сессией.

Ожидаемый результат

  • созданы HTML, Markdown и JSON;
  • в отчёте есть DASHA — Data Acceptance, Screening & Harmonization Agent;
  • в отчёте есть CARA — CAPEX At Risk Agent;
  • в отчёте есть VERA — Verified Execution Reporting Agent;
  • ограниченная детализация объёмов указана явно;
  • фактическое выполнение не подтверждено без актов, фактических объёмов и освоения бюджета.

Что демонстрация не доказывает

Демонстрация не подтверждает универсальную поддержку любых форматов, полноту связки по каждой работе, окончательный бюджет, соблюдение сроков или приёмку выполненных работ. Эти утверждения требуют отдельного сценария, дополнительных источников и профессиональной проверки.
