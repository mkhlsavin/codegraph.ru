Обзор¶

Модуль рефакторинга (src/refactoring/) предоставляет четыре специализированных агента:

  1. TechnicalDebtDetector — обнаруживает запахи кода с помощью библиотеки шаблонов
  2. DeadCodeDetector — специализированный агент для обнаружения мёртвого кода (13 шаблонов + WCC)
  3. ImpactAnalyzer — анализирует влияние изменений и зависимости
  4. RefactoringPlanner — создаёт приоритизированные планы рефакторинга и отчёты

Все агенты, кроме RefactoringPlanner, принимают необязательный CPGQueryService и поддерживают протокол менеджера контекста для автоматического управления ресурсами.

Быстрый старт¶

from src.refactoring import (
    TechnicalDebtDetector,
    DeadCodeDetector,
    ImpactAnalyzer,
    RefactoringPlanner,
)

# Step 1: Detect code smells (context manager auto-creates CPGQueryService)
with TechnicalDebtDetector() as detector:
    findings = detector.detect_all_smells(limit_per_pattern=30)

# Step 2: Analyze impact for all findings
with ImpactAnalyzer() as analyzer:
    impact_analyses = analyzer.analyze_bulk_impact(findings, limit=20)

# Step 3: Create prioritized refactoring plan
planner = RefactoringPlanner()
tasks = planner.create_refactoring_plan(findings, impact_analyses)

# Step 4: Generate report
report = planner.generate_report(findings, impact_analyses, tasks)
print(report.summary)
print(f"Total smells: {report.total_smells}")
print(f"Effort: {report.total_effort_hours:.1f}h")
for rec in report.recommendations:
    print(f"  - {rec}")

Также можно передать существующий CPGQueryService агентам, которые его принимают:

from src.services.cpg import CPGQueryService

cpg_service = CPGQueryService()
detector = TechnicalDebtDetector(cpg_service)
analyzer = ImpactAnalyzer(cpg_service)

Обнаружение запахов кода¶

Поддерживаемые категории шаблонов¶

Категории определены в перечислении CodeSmellCategory (src/refactoring/_base.py):

Категория Значение перечисления Описание Примеры
Раздутый код CodeSmellCategory.BLOATERS Большие методы, длинные списки параметров God Method, Long Parameter List
Злоупотребление ООП CodeSmellCategory.OO_ABUSERS Неправильное использование возможностей ООП Switch Statements, Refused Bequest
Препятствия изменениям CodeSmellCategory.CHANGE_PREVENTERS Шаблоны, затрудняющие внесение изменений Divergent Change, Shotgun Surgery
Избыточный код CodeSmellCategory.DISPENSABLES Мёртвый код, спекулятивная общность Dead Code, Speculative Generality
Связанность CodeSmellCategory.COUPLERS Чрезмерная связанность Feature Envy, Inappropriate Intimacy
Сложность CodeSmellCategory.COMPLEXITY Высокая цикломатическая сложность Deep Nesting, Complex Conditionals
Документация CodeSmellCategory.DOCUMENTATION Отсутствующая или устаревшая документация Missing Comments, Stale Docs

Уровни серьёзности¶

Определены в перечислении CodeSmellSeverity:

Серьёзность Значение перечисления Описание Действие
Критическая CodeSmellSeverity.CRITICAL Серьёзно влияет на сопровождаемость Исправить немедленно
Высокая CodeSmellSeverity.HIGH Существенные проблемы сопровождаемости Исправить в текущем спринте
Средняя CodeSmellSeverity.MEDIUM Умеренный технический долг Запланировать на следующий спринт
Низкая CodeSmellSeverity.LOW Незначительная проблема Исправить при удобном случае
Информационная CodeSmellSeverity.INFO Только для информации Рассмотреть для улучшения

Методы обнаружения¶

Обнаружение всех шаблонов:

with TechnicalDebtDetector() as detector:
    findings = detector.detect_all_smells(limit_per_pattern=30)

    for finding in findings:
        print(f"{finding.severity}: {finding.pattern_name}")
        print(f"  Location: {finding.filename}:{finding.line_number}")
        print(f"  Fix: {finding.refactoring_technique}")

detect_all_smells() перебирает все шаблоны в REFACTORING_PATTERNS, выполняет CPGQL-запрос каждого шаблона и возвращает результаты, отсортированные по серьёзности (критические — первыми).

Обнаружение одного шаблона:

from src.refactoring import REFACTORING_PATTERNS

with TechnicalDebtDetector() as detector:
    pattern = REFACTORING_PATTERNS["GOD_METHOD"]
    findings = detector.detect_pattern(pattern, limit=30)

Обнаружение по категории:

from src.refactoring import CodeSmellCategory

with TechnicalDebtDetector() as detector:
    bloaters = detector.detect_by_category(CodeSmellCategory.BLOATERS, limit=50)
    complexity = detector.detect_by_category(CodeSmellCategory.COMPLEXITY, limit=50)

Примечание: detect_by_category() принимает значение перечисления CodeSmellCategory, а не строку.

Метрики технического долга¶

calculate_debt_metrics() вычисляет агрегированную статистику по находкам:

with TechnicalDebtDetector() as detector:
    findings = detector.detect_all_smells()
    metrics = detector.calculate_debt_metrics(findings)

    print(f"Total smells: {metrics['total_smells']}")
    print(f"Total effort: {metrics['total_effort_hours']:.1f}h")
    print(f"Debt ratio: {metrics['debt_ratio']:.2%}")
    print(f"By severity: {metrics['by_severity']}")
    print(f"By category: {metrics['by_category']}")
    print(f"Avg effort/smell: {metrics['avg_effort_per_smell']:.1f}h")

Возвращает словарь с ключами: total_smells, total_effort_hours, by_severity, by_category, debt_ratio, avg_effort_per_smell.

Обнаружение мёртвого кода¶

DeadCodeDetector — специализированный агент для обнаружения мёртвого кода. Он выполняет 13 шаблонов обнаружения плюс анализ слабо связанных компонентов (WCC) для поиска изолированных компонентов.

Шаблоны обнаружения¶

Идентификатор шаблона Название Тип обнаружения Достоверность
DEAD_CODE Uncalled Functions uncalled 0.70
DEPRECATED_MARKER Deprecated Markers deprecated 0.95
DISABLED_CODE_BLOCK Disabled Code (#if 0) disabled 0.99
UNUSED_VARIABLE Unused Variables unknown 0.50
EMPTY_STUB Empty Stubs stub 0.60
ERROR_ONLY_FUNCTION Error-Only Functions error_only 0.50
UNREACHABLE_AFTER_RETURN Unreachable After Return unreachable 0.90
DEAD_ASSIGNMENT Dead Assignments unknown 0.50
INVARIANT_DEAD_CODE Invariant Dead Code unknown 0.50
DEAD_CALLBACK Dead Callbacks unknown 0.50
SINGLE_CALLER_FUNCTION Single-Caller Functions unknown 0.50
TEST_ONLY_FUNCTION Test-Only Functions unknown 0.50
ORPHAN_COMPONENT Orphan Components (WCC) orphan 0.80

Методы обнаружения мёртвого кода¶

Обнаружение всего мёртвого кода:

with DeadCodeDetector() as detector:
    findings = detector.detect_all(limit_per_pattern=50)

    for finding in findings:
        print(f"[{finding.severity}] {finding.method_name}")
        print(f"  Type: {finding.detection_type}")
        print(f"  Confidence: {finding.confidence:.0%}")
        print(f"  Reason: {finding.reason}")
        print(f"  File: {finding.filename}:{finding.line_number}")

Обнаружение определённых шаблонов:

with DeadCodeDetector() as detector:
    findings = detector.detect_patterns(
        pattern_names=["DEAD_CODE", "DEPRECATED_MARKER", "EMPTY_STUB"],
        limit_per_pattern=30
    )

Обнаружение по типу:

with DeadCodeDetector() as detector:
    # Supported types: uncalled, deprecated, disabled, stub, error_only, unreachable, orphan
    uncalled = detector.detect_by_type("uncalled", limit=50)

Получение сводной статистики:

with DeadCodeDetector() as detector:
    findings = detector.detect_all()
    summary = detector.get_summary(findings)

    print(f"Total findings: {summary['total_findings']}")
    print(f"Total dead lines: {summary['total_lines']}")
    print(f"Avg confidence: {summary['avg_confidence']:.0%}")
    print(f"By type: {summary['by_type']}")
    print(f"By severity: {summary['by_severity']}")
    print(f"By file: {summary['by_file']}")

Анализ изолированных компонентов WCC¶

Метод detect_all() автоматически выполняет анализ WCC (слабо связанных компонентов) в дополнение к обнаружению на основе шаблонов. Анализ WCC использует рекурсивное общее табличное выражение (CTE) по таблице call_containment для выявления методов, недостижимых из точек входа (например, main, *_handler, *_hook, *_init).

Находки изолированных компонентов имеют detection_type="orphan", pattern_id="DEAD_CODE_WCC" и confidence=0.8.

Структура находки мёртвого кода¶

    pattern_id: str
    pattern_name: str
    detection_type: str   # 'uncalled', 'deprecated', 'disabled', 'orphan', etc.
    severity: str
    method_id: int
    method_name: str
    filename: str
    line_number: int
    line_count: int
    code_snippet: str
    reason: str

    metadata: Dict[str, Any] = field(default_factory=dict)

Анализ влияния¶

Анализ изменений методов¶

with ImpactAnalyzer() as analyzer:
    impact = analyzer.analyze_method_impact(
        method_name="heap_insert",
        filename="backend/access/heap/heapam.c"
    )

    print(f"Risk Level: {impact.risk_level}")
    print(f"Impact Score: {impact.impact_score:.2f}")
    print(f"Directly Affected: {len(impact.direct_dependents)} methods")
    print(f"Indirectly Affected: {len(impact.indirect_dependents)} methods")
    print(f"Files to Test: {len(impact.affected_files)}")
    print(f"Estimated Test Effort: {impact.estimated_test_effort:.1f}h")

Вычисление оценки влияния: - impact_score = min(direct_count * 0.1 + indirect_count * 0.05, 1.0) - Уровни риска: high (оценка > 0.7 или > 20 прямых зависимостей), medium (оценка > 0.4 или > 10 прямых зависимостей), low (в остальных случаях)

Массовый анализ влияния¶

analyze_bulk_impact() выполняет analyze_method_impact() для каждой находки:

with ImpactAnalyzer() as analyzer:
    impact_analyses = analyzer.analyze_bulk_impact(findings, limit=20)

    for ia in impact_analyses:
        print(f"{ia.target_method}: risk={ia.risk_level}, score={ia.impact_score:.2f}")

Структура анализа влияния¶

@dataclass
class ImpactAnalysis:
    analysis_id: str
    target_method: str
    target_file: str
    direct_dependents: List[str]    # Methods that call target
    indirect_dependents: List[str]  # Transitive callers
    affected_files: List[str]       # Files needing review
    impact_score: float             # 0.0 to 1.0
    risk_level: str                 # "low", "medium", "high"
    estimated_test_effort: float    # Hours

Анализ зависимостей¶

with ImpactAnalyzer() as analyzer:
    deps = analyzer.find_dependencies("heap_insert", depth=2)

    for dep in deps:
        print(f"{dep.from_method} -> {dep.to_method}")
        print(f"  Type: {dep.dependency_type}")
        print(f"  Strength: {dep.strength}")

find_dependencies() выполняет запрос к таблице call_containment для поиска как вызывающих, так и вызываемых методов для заданного метода.

Структура DependencyInfo¶

@dataclass
class DependencyInfo:
    dependency_id: str
    from_method: str
    from_file: str
    to_method: str
    to_file: str
    dependency_type: str  # "calls", "includes", "data"
    strength: str         # "strong", "medium", "weak"

Планирование рефакторинга¶

RefactoringPlanner не принимает аргументов конструктора. Он работает с находками и результатами анализа влияния, полученными от других агентов.

Создание плана рефакторинга¶

planner = RefactoringPlanner()

# create_refactoring_plan() returns List[RefactoringTask] directly
tasks = planner.create_refactoring_plan(findings, impact_analyses)

for task in tasks:
    print(f"\nTask {task.task_id}: {task.pattern_name}")
    print(f"  Target: {task.target_file}:{task.target_method}")
    print(f"  Priority: {task.priority}/10")
    print(f"  Effort: {task.effort_hours}h")
    print(f"  Value: {task.estimated_value:.1f}")
    print(f"  Impact: {task.impact_score:.2f}")
    print(f"  Steps:")
    for step in task.refactoring_steps:
        print(f"    - {step}")

Приоритизация задач¶

Задачи сортируются по приоритету (наивысший — первым), затем по ROI (ценность / трудозатраты). Приоритет вычисляется на основе:

  1. Серьёзность — базовая оценка по уровню серьёзности (critical=10, high=7, medium=4, low=2, info=1)
  2. Риск влияния — низкий риск корректирует приоритет на +1, высокий риск — на -1
  3. Бонус категории — раздутый код получает +2 к приоритету (влияет на многие другие запахи)

Структура задачи рефакторинга¶

@dataclass
class RefactoringTask:
    task_id: str
    finding_id: str
    pattern_name: str
    target_method: str
    target_file: str
    priority: int              # 1-10, higher = more urgent
    effort_hours: float
    impact_score: float
    refactoring_steps: List[str]
    dependencies: List[str]    # Other tasks that should be done first
    estimated_value: float     # Benefit of completing this task

Отчёт по рефакторингу¶

Генерация полного отчёта¶

generate_report() требует три позиционных аргумента: находки, результаты анализа влияния и задачи.

planner = RefactoringPlanner()
tasks = planner.create_refactoring_plan(findings, impact_analyses)
report = planner.generate_report(findings, impact_analyses, tasks)

print(report.summary)
print(f"Total smells: {report.total_smells}")
print(f"By severity: {report.by_severity}")
print(f"By category: {report.by_category}")
print(f"Effort: {report.total_effort_hours:.1f}h")
print(f"Estimated value: {report.estimated_value:.1f}")
for rec in report.recommendations:
    print(f"  - {rec}")

Структура отчёта¶

@dataclass
class RefactoringReport:
    report_id: str
    timestamp: str                          # ISO format string
    total_smells: int
    by_severity: Dict[str, int]             # e.g. {"critical": 2, "high": 5}
    by_category: Dict[str, int]             # e.g. {"bloaters": 3, "complexity": 4}
    findings: List[CodeSmellFinding]
    impact_analyses: List[ImpactAnalysis]
    tasks: List[RefactoringTask]
    total_effort_hours: float
    estimated_value: float
    summary: str                            # Executive summary text
    recommendations: List[str]              # Prioritized recommendations

Поддерживаемые шаблоны¶

Шаблоны раздутого кода¶

Шаблон Обнаружение Техника
God Method Строк > 200, сложность > 20 Extract Method
Long Parameter List Параметров > 5 Introduce Parameter Object
Large Class Методов > 30 Extract Class
Data Clumps Повторяющиеся группы параметров Extract Class

Шаблоны сложности¶

Шаблон Обнаружение Техника
Complex Conditionals Глубина вложенности > 4 Decompose Conditional
Deep Nesting Глубина вложенности > 5 Extract Method, Guard Clauses

Шаблоны избыточного кода¶

Шаблон Обнаружение Техника
Dead Code Невызываемые методы Remove Method
Speculative Generality Неиспользуемые абстракции Remove Abstraction

Шаблоны злоупотребления ООП¶

Шаблон Обнаружение Техника
Switch Statements Размер switch > 5 ветвей Replace with Polymorphism
Refused Bequest Неиспользуемые унаследованные методы Replace Inheritance with Delegation

Шаблоны препятствий изменениям¶

Шаблон Обнаружение Техника
Divergent Change Много причин для изменения одного класса Extract Class

SQL-запросы для обнаружения¶

Модуль использует SQL-запросы к графу свойств кода (CPG) для обнаружения шаблонов. Каждый RefactoringPattern содержит поле cpgql_query с SQL-запросом обнаружения.

Длинные методы (раздутый код):

SELECT m.name, m.full_name, m.filename, m.line_number,
       (m.line_number_end - m.line_number) AS lines
FROM nodes_method m
WHERE (m.line_number_end - m.line_number) > 200
  AND m.is_external = false
ORDER BY lines DESC;

Высокая сложность:

SELECT m.name, m.filename, COUNT(cs.id) AS complexity
FROM nodes_method m
JOIN edges_ast a ON m.id = a.src
JOIN nodes_control_structure cs ON a.dst = cs.id
WHERE cs.control_structure_type IN ('IF', 'WHILE', 'FOR', 'SWITCH')
GROUP BY m.id, m.name, m.filename
HAVING COUNT(cs.id) > 15
ORDER BY complexity DESC;

Невызываемые методы (мёртвый код):

SELECT m.name, m.full_name, m.filename
FROM nodes_method m
WHERE m.is_external = false
  AND NOT EXISTS (
      SELECT 1 FROM edges_call ec WHERE ec.dst = m.id
  )
  AND m.name NOT LIKE 'test%'
  AND m.name NOT IN ('main', 'init');

Обнаружение изолированных компонентов WCC (рекурсивное CTE по call_containment):

WITH RECURSIVE reachable(name, id, filename, line_number, line_count, depth) AS (
    SELECT DISTINCT m.name, m.id, m.filename, m.line_number,
           (m.line_number_end - m.line_number) AS line_count, 0 AS depth
    FROM nodes_method m
    WHERE m.name = 'main'
       OR m.name LIKE '%_handler'
       OR m.name LIKE '%_hook'
       OR m.name LIKE '%_init'
    LIMIT 100

    UNION

    SELECT DISTINCT m.name, m.id, m.filename, m.line_number,
           (m.line_number_end - m.line_number) AS line_count, r.depth + 1 AS depth
    FROM nodes_method m
    JOIN call_containment c ON c.callee_name = m.name
    JOIN reachable r ON c.containing_method_name = r.name
    WHERE m.name NOT LIKE 'test_%'
      AND r.depth < 2
    LIMIT 500
)
SELECT DISTINCT m.id, m.name AS method_name, m.filename, m.line_number,
       (m.line_number_end - m.line_number) AS line_count
FROM nodes_method m
WHERE m.name NOT IN (SELECT name FROM reachable)
  AND m.name NOT LIKE 'test_%'
  AND (m.line_number_end - m.line_number) > 5
ORDER BY (m.line_number_end - m.line_number) DESC
LIMIT 50;
