Чеклисты тестирования DASHA, SARA и VERA

Используйте статусы «пройдено», «не пройдено», «заблокировано» и «не применимо». Проверки общего контракта не должны зависеть от имён файлов и листов текущей демонстрации.

Общий контракт ролей¶

  • [ ] В пользовательском представлении есть точные названия DASHA, SARA и VERA.
  • [ ] Внутренние ID и схема машинного отчёта сохраняют обратную совместимость.
  • [ ] Формат и количество входных документов описаны как параметры сценария, а не как неизменное требование ролей.
  • [ ] Каждая роль показывает статус входа, проверенные поверхности, выводы и ограничения.
  • [ ] Блокировка входа не превращается в успешный или уверенный вывод.
  • [ ] Роли не смешиваются с цифровыми сотрудниками внутреннего SDLC CodeGraph.

DASHA — Data Acceptance, Screening & Harmonization Agent¶

  • [ ] Назначение сформулировано как входной контроль проектных данных в целом.
  • [ ] Проверяются доступность, тип, структура, полнота и пригодность данных.
  • [ ] Повреждённый, неподдерживаемый или отсутствующий вход блокируется понятным сообщением.
  • [ ] Формулы, макросы и внешние ссылки не исполняются молча.
  • [ ] Оценка качества не выдаётся за доказательство инженерной корректности данных.
  • [ ] Требования к XLSM и конкретным листам помечены как условия текущего учебного профиля.

SARA — CAPEX At Risk Agent¶

  • [ ] Фокус вывода — CAPEX at risk в связке стоимости, сроков, объёмов и объектов.
  • [ ] Риск отделён от пробела данных, конфликта сопоставления, допущения и известного ограничения.
  • [ ] При отсутствии устойчивого общего ключа совпадение по названию не выдаётся за точное.
  • [ ] Наличие физических объёмов подтверждается данными, а не только названием листа.
  • [ ] В текущем учебном профиле объёмы отмечены как присутствующие, но с ограниченной детализацией: допускается проверка «стоимость — объём — объект», но не полная связка по каждой работе.
  • [ ] Известная неполнота учебного набора не превращается в автоматический CAPEX-риск.
  • [ ] Для каждого наблюдения в машинном отчёте остаётся локальная ссылка на доказательство.

VERA — Verified Execution Reporting Agent¶

  • [ ] Плановый или заявленный процент в графике не называется подтверждённым фактом.
  • [ ] Для сильного вывода запрашиваются акты, фактические объёмы и освоение бюджета.
  • [ ] При отсутствии подтверждений статус остаётся ограниченным, а уверенность — неполной.
  • [ ] Аномальные проценты и последовательности дат выделяются для ручной проверки.
  • [ ] Вывод не оценивает подрядчика, если набор подтверждает лишь график или статус.

Текущий учебный пример¶

  • [ ] В папке примеров находится ровно один ожидаемый XLSM и один PDF.
  • [ ] Команда python scripts/run_investment_construction_agents_e2e.py завершается без необработанного исключения.
  • [ ] Созданы JSON, Markdown и автономный HTML.
  • [ ] HTML содержит пометку «Учебный сценарий: текущий набор XLSM + PDF».
  • [ ] HTML не содержит скриптов, внешних ресурсов, исходных путей или активных ссылок.
  • [ ] В HTML видны три независимые карточки и текстовые статусы, понятные без цвета.
  • [ ] На узком экране карточки перестраиваются в одну колонку.
  • [ ] В печатном режиме отчёт остаётся читаемым.
  • [ ] При отсутствии обоих файлов все три роли блокируются, а HTML всё равно создаётся.

Итог приёмки¶

  • [ ] Общая документация и демо-сценарий разведены.
  • [ ] Все точечные замечания заказчика отражены в манифесте, описании поведения и UI.
  • [ ] JSON v2 и внутренние employee ID не изменены.
  • [ ] Человек может за пять минут объяснить назначение ролей и ограничения набора.
  • [ ] Ни один процент выполнения не представлен подтверждённым фактом без достаточных документов.
