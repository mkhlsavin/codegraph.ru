Чеклисты тестирования Даши, Сары и Веры Прогресс

Этот документ нужен, чтобы тестировать сотрудников одинаково и не спорить о том, что считается успешной проверкой.

Каждый пункт отмечайте одним из четырех статусов:

  • пройдено;
  • не пройдено;
  • заблокировано;
  • не применимо.

Общая подготовка¶

  • [ ] Проверить, что есть сметный файл.
  • [ ] Проверить, что есть файл графика.
  • [ ] Проверить, что оба файла лежат в ожидаемой папке.
  • [ ] Запустить общую проверку командой python scripts\run_investment_construction_agents_e2e.py.
  • [ ] Убедиться, что создан отчет для чтения человеком.
  • [ ] Убедиться, что создан машинный отчет.
  • [ ] Убедиться, что в отчете есть три сотрудника: Даша, Сара и Вера Прогресс.
  • [ ] Убедиться, что новые сотрудники не добавлены в реестр сотрудников разработки.
  • [ ] Убедиться, что Вера Прогресс не называется просто Верой.

Чеклист Даши¶

Входные файлы¶

  • [ ] Даша получает именно сметный файл.
  • [ ] Файл читается без запуска макросов.
  • [ ] Ошибка чтения файла отражается в отчете понятным сообщением.
  • [ ] Поврежденный файл не приводит к ложному успешному выводу.

Листы¶

  • [ ] Даша находит лист «Реестр смет».
  • [ ] Даша находит лист «Сводка затрат».
  • [ ] Даша находит лист «ВФО-Техн.К».
  • [ ] Даша не путает рабочие листы с техническими листами.
  • [ ] Даша учитывает лишние пробелы в названиях листов.
  • [ ] Даша возвращает в отчете нормальные названия листов без лишних пробелов.

Содержимое¶

  • [ ] Даша проверяет, что обязательные листы не пустые.
  • [ ] Даша видит строки и столбцы на обязательных листах.
  • [ ] Даша сообщает о пустом обязательном листе как о пробеле данных.
  • [ ] Даша сообщает об отсутствующем обязательном листе как о критичном пробеле данных.
  • [ ] Даша не делает вывод о корректности сметных формул, если формулы не проверялись.

Итог Даши¶

  • [ ] В отчете есть оценка качества данных.
  • [ ] Оценка качества данных не меньше нуля.
  • [ ] При полном наличии обязательных листов оценка выше, чем при пропущенном листе.
  • [ ] Итог написан понятным языком.
  • [ ] Итог разделяет «можно продолжать проверку» и «данные полностью верны».

Чеклист Сары¶

Входные файлы¶

  • [ ] Сара получает сметный файл.
  • [ ] Сара получает файл графика.
  • [ ] Сара использует оба файла в одном выводе.
  • [ ] Если одного файла нет, Сара не делает полный вывод по связке стоимости и графика.

Сопоставление¶

  • [ ] Сара проверяет стоимость.
  • [ ] Сара проверяет физические объемы.
  • [ ] Сара проверяет объекты.
  • [ ] Сара проверяет график.
  • [ ] Сара сообщает, что между файлами нет надежного общего ключа, если он не найден.
  • [ ] Сара не выдает слабое сопоставление как точное совпадение.

Классы выводов¶

  • [ ] Сара умеет выдать риск капитальных затрат.
  • [ ] Сара умеет выдать пробел данных.
  • [ ] Сара умеет выдать известное ограничение.
  • [ ] Каждый вывод имеет понятное название.
  • [ ] Каждый вывод имеет объяснение причины.
  • [ ] Каждый вывод имеет ссылку на источник.

Известная неполнота¶

  • [ ] Сара знает, что по корпусу классификации есть неполнота по закупке материалов и оборудования.
  • [ ] Сара знает, что по складу реагентов есть неполнота по строительно-монтажным работам.
  • [ ] Сара не превращает эту известную неполноту в автоматический риск капитальных затрат.
  • [ ] Сара помечает известную неполноту как ограничение набора данных.

Итог Сары¶

  • [ ] В отчете есть отдельный список рисков.
  • [ ] В отчете есть отдельный список пробелов данных.
  • [ ] В отчете есть отдельный список известных ограничений.
  • [ ] Сара объясняет, какие вопросы нужно задать владельцу данных.
  • [ ] Сара не утверждает, что вся стоимость, все объемы и весь график полностью согласованы.

Чеклист Веры Прогресс¶

Входные файлы¶

  • [ ] Вера Прогресс получает файл графика.
  • [ ] Вера Прогресс может прочитать количество страниц или другой базовый признак файла.
  • [ ] Вера Прогресс не требует сметный файл для проверки самого графика.
  • [ ] Если график не читается, отчет говорит об этом прямо.

План и статус¶

  • [ ] Вера Прогресс проверяет структуру работ.
  • [ ] Вера Прогресс проверяет плановые даты.
  • [ ] Вера Прогресс проверяет длительность.
  • [ ] Вера Прогресс проверяет процент выполнения.
  • [ ] Вера Прогресс ищет странные сочетания дат, длительности и статуса.
  • [ ] Вера Прогресс не считает процент выполнения доказанным фактом без подтверждающих документов.

Недостающие подтверждения¶

  • [ ] Вера Прогресс сообщает, что не хватает актов выполненных работ.
  • [ ] Вера Прогресс сообщает, что не хватает фактических объемов.
  • [ ] Вера Прогресс сообщает, что не хватает данных об освоении бюджета.
  • [ ] Вера Прогресс снижает уверенность вывода, если этих документов нет.
  • [ ] Вера Прогресс не пишет, что фактический прогресс полностью подтвержден.

Итог Веры Прогресс¶

  • [ ] В отчете есть проверенная поверхность «график».
  • [ ] В отчете есть список недостающих документов.
  • [ ] В отчете есть оценка уверенности по прогрессу.
  • [ ] Оценка уверенности меньше полной, если есть только график.
  • [ ] Вывод написан как осторожное ограничение, а не как ошибка пользователя.

Общий итоговый чеклист приемки¶

  • [ ] Даша завершила проверку.
  • [ ] Сара завершила проверку.
  • [ ] Вера Прогресс завершила проверку.
  • [ ] Отчет содержит выводы всех трех сотрудников.
  • [ ] Отчет не смешивает новых сотрудников с сотрудниками процесса разработки.
  • [ ] Отчет не использует Веру Прогресс как сотрудницу по безопасности.
  • [ ] Машинный отчет создан.
  • [ ] Читаемый отчет создан.
  • [ ] Все найденные ограничения сформулированы без лишней тревоги.
  • [ ] Все сильные выводы имеют достаточные источники.
  • [ ] Если источников недостаточно, отчет прямо говорит, чего не хватает.

Чеклист ручной проверки результата¶

  • [ ] Пользователь понимает, какие файлы были проверены.
  • [ ] Пользователь понимает, что Даша проверяет входные данные, а не строительный факт.
  • [ ] Пользователь понимает, что Сара ищет риски и разрывы, а не утверждает окончательный бюджет.
  • [ ] Пользователь понимает, что Вера Прогресс не подтверждает факт без актов, объемов и бюджета.
  • [ ] Пользователь может передать отчет сметчику, планировщику или руководителю проекта без дополнительного перевода.
