Руководства по CodeGraph

Материал «Руководства по CodeGraph» содержит рабочие сведения по разделу «Руководства» и описывает применение CodeGraph.

РуководстваОбновлено: 2026-08-08

Этот раздел объясняет, как пользоваться CodeGraph в реальной работе.

Если запомнить только одну мысль, то она такая:

  • GoCPG показывает живую структуру кода.
  • OpenViking хранит общую память проекта и рабочие сессии.
  • PostgreSQL управляет владельцами, передачей сессий, правами доступа и состоянием знаний.
  • OpenCode — основной рабочий интерфейс для разработчика, ревьюера и тестировщика.

Простая модель системы

У CodeGraph три главных слоя:

  1. GoCPG отвечает на вопросы о структуре кода, вызовах, потоках данных и зависимостях.
  2. OpenViking хранит полезный контекст проекта, память рабочих сессий и подготовленные навыки.
  3. PostgreSQL решает, кто владеет сессией, кто может её открыть повторно, кому её можно передать и насколько можно доверять сохранённым знаниям.

Из этого вытекают новые практические возможности:

  • задавать вопросы по живому коду;
  • возвращаться к той же рабочей сессии после паузы;
  • передавать сессию между разработчиком, ревьюером и тестировщиком;
  • не подмешивать в ответы устаревшие знания.

Основные способы работы

Плагин OpenCode

Это основной путь для ежедневной работы.

Обычно используются такие команды:

  • /onboard
  • /review
  • /continue
  • /status
  • /update
  • /explain

Читайте: Быстрый старт OpenCode

CLI

Этот путь нужен для автоматизации, пакетных операций и запуска из CI.

Обычно через него:

  • импортируют проект;
  • обновляют контекст проекта;
  • запускают проверки и отчёты;
  • смотрят состояние системы.

Читайте: Руководство по CLI

API и MCP

Этот путь нужен, если вы встраиваете CodeGraph в другой инструмент или агент.

Обычно через него:

  • открывают и переоткрывают сессии;
  • получают контекст проекта;
  • читают сохранённую память;
  • сохраняют полезный контекст обратно;
  • проверяют состояние знаний.

Читайте:

Что изменилось в новой архитектуре

Раньше многие руководства были завязаны почти только на граф кода и векторный поиск. Теперь рабочая модель шире:

  • сессии стали явными и управляемыми;
  • одну и ту же сессию можно передавать между людьми и инструментами внутри проекта;
  • знания имеют состояния «актуально», «требует проверки» и «устарело»;
  • система умеет безопасно работать даже при временной недоступности слоя памяти.
