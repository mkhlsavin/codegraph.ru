Документация / Руководства

Руководства

ДокументацияОбновлено: 2026-08-29
  • Краткий справочник CodeGraph Используйте страницу для выбора entry point, затем откройте live --help команды или подробное руководство. Root CLI из source checkout начинается с python.
  • Командная строка CodeGraph Корневой CLI CodeGraph работает из source checkout. В корне репозитория используйте: Не считайте, что установка Python wheel создаёт executable codegraph.
  • Типизированный вызов сценария CodeGraph экспортирует один типизированный Python-контракт для role-bound выполнения сценария. Он подходит для внутрипроцессной интеграции, уже связанной.
  • Импорт проекта в CodeGraph Импорт создаёт или обновляет именованный проект из локального checkout либо Git-репозитория. Запускайте его из source checkout CodeGraph в tenant/group.
  • Review ограниченного изменения кода CodeGraph объединяет quality- и security-findings для явного Git diff, staged changes или списка файлов. Профессиональный reviewer использует эти находки.
  • Хуки проверки кода для Codex и Claude Code Настройка и проверка поставляемых с CodeGraph хуков Codex и Claude Code с точками жизненного цикла и блокирующими границами.
  • Бенчмарк пилота Это руководство помогает сравнить небольшой согласованный набор задач заказчика с базовой линией. Команда формирует пакет для решения; выполнение задач.
  • Мониторинг промышленной установки Это руководство описывает подключение CodeGraph к внешнему контуру Prometheus и Alertmanager. Каталог метрик и выражения оповещений не копируются в.
  • Безопасная диагностика CodeGraph Начинайте с read-only evidence. Не перезапускайте сервисы, не исправляйте state, не удаляйте данные и не меняйте project scope, пока профессиональный.
  • Эксплуатация dogfood-проверок Актуальный CLI-процесс проверки свежести CPG, анализа коммитов, динамики качества и управляемого восстановления.
  • Анализ потоков данных безопасности Dataflow analysis находит candidate paths от недоверенных sources к чувствительным sinks. Он помогает профессиональному security reviewer расставить.
  • LSP-сервер CodeGraph Языковой сервер CodeGraph передаёт LSP-клиенту информацию о коде из графа. Он читает существующий DuckDB CPG под управлением GoCPG, но не строит и не.
  • Быстрый старт OpenCode с CodeGraph Репозиторный launcher настраивает MCP-сервер CodeGraph, LSP и plugin opencode-codegraph для текущего checkout. Перед запуском импортируйте проект и.
  • Каталог сценариев Каталог актуальных публичных сценариев CodeGraph по пользовательским задачам с границами безопасного применения и доказательств.
  • Сценарий 01: знакомство с незнакомой кодовой базой Используйте этот сценарий, когда перед вопросами или изменениями нужна достоверная первичная карта репозитория.
  • Сценарий 02: ограниченный аудит безопасности Используйте этот сценарий, чтобы проверить заданную рабочую область или набор изменений и получить структурные находки, связанные с безопасностью.
  • Предварительные исправления аудита безопасности Используйте autofix после того, как находка безопасности ограничена конкретным методом и, при необходимости, CWE.
  • Сценарий 03: документация по проверенным исходникам Используйте этот сценарий, когда у задачи есть определённый читатель, ограниченная тема, принятый идентификатор задачи и актуальные свидетельства из.
  • Сценарий 04: разработка ограниченной функции Используйте этот сценарий после согласования продуктового результата, области задачи, критериев приёмки и линий свидетельств.
  • Сценарий 05: рефакторинг с проверкой влияния Используйте этот сценарий, когда нужно изменить структуру кода и сохранить поведение продукта. CodeGraph показывает область влияния, помогает сравнить.
  • Сценарий 06: исследование проблемы производительности Используйте этот сценарий, когда есть измеренная проблема задержки, пропускной способности, CPU, памяти, ввода-вывода или конкуренции и нужно сузить.
  • Сценарий 07: поиск и приоритизация тестовых пробелов Используйте этот сценарий, чтобы совместить доступное runtime-покрытие со структурными свидетельствами: вызывающим кодом, точками входа и ссылками на.
  • Сценарий 08: сбор свидетельств соответствия Используйте этот сценарий для ответа на один ограниченный вопрос по именованным требованиям, области и ревизии.
  • Сценарий 09: ревью ограниченного изменения Используйте этот сценарий для pull request, диапазона коммитов, staged-изменения или заданного набора файлов. Полезное ревью привязано к точным базовой и.
  • Сценарий 10: межрепозиторное влияние Проверка зависимостей, дублирования и рисков консолидации между репозиториями без подмены анализа архитектурным решением.
  • Сценарий 11: анализ архитектуры Сценарий помогает исследовать зависимости, циклы, нарушения слоёв, связанность и структурные риски внутри одного проекта.
  • Сценарий 12: планирование технического долга Используйте сценарий 12, чтобы исследовать ограниченный вопрос о долге и подготовить предложение по его погашению.
  • Сценарий 13: план массового рефакторинга Сценарий 13 находит использования, группирует кандидатов миграции, оценивает влияние на места вызова и предлагает порядок работ.
  • Сценарий 14: расследование инцидента ИБ Сценарий 14 ищет вызывающие функции, точки входа, уязвимые использования и доступные потоки данных для конкретного вопроса об инциденте.
  • Сценарий 15: исследование ошибки Сценарий 15 находит логирование, assertions, trace points, помощники стека, кандидаты для breakpoint и другие конструкции, связанные с одним вопросом об.
  • Сценарий 16: точки входа и поверхность атаки Сценарий 16 ищет в CPG проекта внешние, сетевые, запросные, аутентификационные, файловые, процессные и связанные кандидаты в точки входа.
  • Сценарий 18: анализ оптимизации кода Сценарий 18 анализирует ограниченный набор файлов и возвращает предложения по категориям. Текущий публичный контракт имеет режим analysis-only: ни один.
  • Сценарий 19: проверка стандартов Импорт явных правил и ограниченная проверка с сохранением операционного свидетельства без подмены compliance-решения.
  • Сценарий 20: анализ зависимостей Инвентаризируйте зависимости проекта и собирайте ограниченные свидетельства об уязвимостях, лицензиях, SBOM и состоянии без завышения покрытия источников.
  • Методология оценки состояния проекта Это руководство нужно, если показатель дашборда влияет на приоритеты, оценку риска или решение о выпуске. Здесь описано, из чего складывается итоговый.
  • Эксплуатация дашборда Этот runbook описывает операции именно с дашбордом: проверку актуальности поверхности проекта, первичную настройку уведомлений, сохранение воспроизводимых.
  • Руководство пользователя дашборда Дашборд объединяет сигналы проекта, портфеля, безопасности, выпуска и управления в рабочих областях. Здесь удобно найти проблему и её доказательства.
  • Цифровые сотрудники для инвестиционно-строительного контроля CodeGraph объединяет три специализированные роли в управляемый аналитический процесс. Они проверяют качество входных данных, находят кандидатов в.
  • Как работать с DASHA, CARA и VERA Это руководство описывает поддерживаемый сценарий в уже развёрнутом экземпляре CodeGraph. Параметры установки, адрес сервера и способ входа получите у.
  • Структурный поиск шаблонов и управляемое переписывание Выполняйте структурный поиск GoCPG с явной областью, а любые изменения исходников проводите через предпросмотр, подтверждение, резервную копию и проверку.
  • Эксплуатационный release gate Release gate CodeGraph объединяет настроенные проверки безопасности, качества, тестов, compliance и ревью в эксплуатационное решение по выбранному проекту.
  • Формирование SBOM и аудит зависимостей SBOM фиксирует обнаруженные компоненты и версии. SCA audit сопоставляет inventory с источниками уязвимостей и policy thresholds.
  • Оценка рисков цепочки поставок ПО Supply-chain analysis проверяет provenance, integrity, publisher trust, registry metadata и typosquatting. SCA/SBOM остаётся отдельным источником состава.
  • Построение и сопровождение STRIDE threat model CodeGraph выводит candidate assets, processes, data stores, flows, trust boundaries и STRIDE threats из текущего CPG.
  • Составные аналитические workflow Объединяйте находки сценария 18 или 19 через поддерживаемый CLI либо управляемый MCP-маршрут, не выдавая предложения за применённые изменения.
