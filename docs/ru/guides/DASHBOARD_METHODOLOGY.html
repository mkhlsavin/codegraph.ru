Руководство по методологии дашборда

Этот документ объясняет, что на самом деле должен означать итоговый балл на дашборде.

Самая важная мысль такая:

Баллы полезны только тогда, когда понятно, какую реальность они сжимают в одно число.

Что должен отражать итоговый балл¶

Полезный балл должен учитывать не только количество дефектов.

Он должен удерживать баланс между:

  • здоровьем кода;
  • рисками ревью;
  • состоянием соответствия требованиям;
  • готовностью к выпуску;
  • доверием к контексту проекта.

Почему методология стала важнее именно сейчас¶

В новой архитектуре у проекта может быть:

  • приемлемое качество кода;
  • слабая непрерывность сессий;
  • устаревшая память проекта;
  • деградация извлечения контекста.

Если итоговый балл этого не учитывает, число начинает вводить в заблуждение.

Хороший принцип расчёта¶

Хороший итоговый балл должен снижаться, если:

  • память проекта устаревает;
  • синхронизация слишком долго отстаёт;
  • появляются блокеры выпуска;
  • копятся важные замечания;
  • проблемы управления доступом уже влияют на реальную работу.
