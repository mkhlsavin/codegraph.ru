Методология Health Score дашборда V2

Методология Health Score дашборда V2¶

Описание расчёта составного показателя качества Health Score, присвоения оценок и классификации уровней риска в портфельном дашборде CISO/CTO V2.

Обзор¶

Health Score — числовой показатель от 0 до 100, отражающий общий уровень безопасности и качества проекта. Он агрегирует пять независимых компонентов, каждый из которых измеряет отдельное измерение качества. Чем выше балл, тем здоровее проект.

Показатель используется для: - Присвоения оценки (A–F) - Классификации уровня риска (low / medium / high / critical) - Мониторинга зоны риска в портфеле - Отслеживания трендов во времени

Составная формула¶

health_score = (
    audit_component      * W_audit      +
    compliance_component * W_compliance +
    release_component    * W_release    +
    sca_component        * W_sca        +
    quality_component    * W_quality
) * 100

Каждый компонент принимает значение в диапазоне [0.0, 1.0]. Веса по умолчанию:

Компонент Вес по умолчанию Поле в config.yaml
Аудит 0.30 weight_audit
Соответствие 0.25 weight_compliance
Ворота выпуска 0.20 weight_release
SCA 0.15 weight_sca
Качество 0.10 weight_quality
Итого 1.00 —

Веса настраиваются в config.yaml в разделе dashboard:. Их сумма должна точно равняться 1.0.

Компоненты¶

Компонент аудита¶

Отражает результат прохождения сценария аудита безопасности CodeGraph.

audit_component = audit_score / 10.0
  • audit_score — балл аудита по шкале 0–10, возвращаемый системой запуска аудита.
  • Балл 10.0 даёт audit_component = 1.0 (максимальный вклад).
  • Балл 0.0 даёт audit_component = 0.0.

Компонент соответствия¶

Отражает долю процессов ГОСТ Р 56939, требования к которым выполнены.

compliance_component = compliance_pct / 100.0
  • compliance_pct — процент (0–100) из системы проверки соответствия.
  • Полное покрытие (100%) даёт compliance_component = 1.0.

Компонент ворот выпуска¶

Преобразует статус ворот выпуска в числовое значение.

release_map = {
    "pass": 1.0,
    "warn": 0.5,
    "fail": 0.0
}
release_component = release_map[release_status]
Статус Значение Значение
pass 1.0 Все проверки пройдены
warn 0.5 Некоторые проверки выдали предупреждения
fail 0.0 Одна или несколько проверок не пройдены

Компонент SCA¶

Отражает нагрузку уязвимостей SCA/SBOM. Критические и высокие уязвимости штрафуют сильнее, чем средние.

sca_component = max(0.0, 1.0 - (sca_critical * 0.15 + sca_high * 0.08 + sca_medium * 0.02))
Серьёзность Штраф за уязвимость
Критическая 0.15
Высокая 0.08
Средняя 0.02

Результат ограничивается диапазоном [0.0, 1.0]. Проект без уязвимостей SCA имеет sca_component = 1.0.

Пример: 2 критических + 3 высоких + 5 средних = 1 - (0.30 + 0.24 + 0.10) = 0.36.

Компонент качества¶

Измеряет качество кода по четырём равновесным подпоказателям.

quality_component = (
    test_coverage       * 0.4 +
    doc_coverage        * 0.2 +
    (1 - dead_ratio)    * 0.2 +
    (1 - cc_normalized) * 0.2
)
Подпоказатель Вес Описание
test_coverage 0.4 Покрытие строк кода модульными тестами (0.0–1.0)
doc_coverage 0.2 Доля задокументированных публичных функций (0.0–1.0)
1 - dead_ratio 0.2 1 минус доля мёртвого кода (0.0–1.0)
1 - cc_normalized 0.2 1 минус нормализованная цикломатическая сложность (0.0–1.0)
  • dead_ratio — доля функций, помеченных как мёртвый код.
  • cc_normalized — цикломатическая сложность, нормализованная в [0.0, 1.0] делением на настраиваемый максимум (analysis.complexity_threshold).

Пороги оценок¶

Значения Health Score отображаются на буквенные оценки следующим образом:

Оценка Минимальный балл Значение
A ≥ 85 Отлично — проект готов к выпуску в промышленную эксплуатацию
B ≥ 70 Хорошо — незначительные проблемы, блокировщиков нет
C ≥ 55 Удовлетворительно — несколько проблем требуют внимания
D ≥ 40 Плохо — значительные проблемы
F < 40 Критично — выпуск проекта недопустим

Пороги настраиваются:

dashboard:
  grade_a_min: 85.0
  grade_b_min: 70.0
  grade_c_min: 55.0
  grade_d_min: 40.0

Уровни риска¶

Уровни риска объединяют значение Health Score с дополнительными условиями и дают операционную классификацию, используемую для оповещений и мониторинга зоны риска.

Уровень риска Условие
critical Health Score < 40 ИЛИ sca_critical > 0 ИЛИ compliance_pct < 40%
high Health Score < 55 ИЛИ статус ворот выпуска = fail
medium Health Score < 70 ИЛИ статус ворот выпуска = warn
low Health Score ≥ 70 И статус ворот выпуска = pass

Присваивается наивысший подходящий уровень риска. Например, проект с баллом 72, но со статусом ворот выпуска fail получит уровень high, а не low.

Пороги уровней риска настраиваются:

dashboard:
  risk_critical_max_score: 40.0  # максимальный балл для уровня "critical"
  risk_high_max_score: 55.0      # максимальный балл для уровня "high"
  risk_medium_max_score: 70.0    # максимальный балл для уровня "medium"

Примеры расчётов¶

Пример 1: Здоровый проект¶

Входные данные Значение
audit_score 9.0
compliance_pct 94%
release_status pass
sca_critical 0, sca_high
test_coverage 0.85, doc_coverage

Компоненты:

audit_component      = 9.0 / 10.0                          = 0.900
compliance_component = 94 / 100                            = 0.940
release_component    = 1.0   (pass)
sca_component        = 1.0 - (0 + 0.08 + 0.04)            = 0.880
quality_component    = 0.85*0.4 + 0.75*0.2 + 0.95*0.2 + 0.80*0.2
                     = 0.340 + 0.150 + 0.190 + 0.160       = 0.840

Health Score:

= (0.900*0.30 + 0.940*0.25 + 1.0*0.20 + 0.880*0.15 + 0.840*0.10) * 100
= (0.270 + 0.235 + 0.200 + 0.132 + 0.084) * 100
= 0.921 * 100 = 92.1

Оценка: A — Уровень риска: low

Пример 2: Проект с уязвимостями SCA¶

Входные данные Значение
audit_score 7.5
compliance_pct 78%
release_status warn
sca_critical 2, sca_high
test_coverage 0.60, doc_coverage

Компоненты:

audit_component      = 7.5 / 10.0                          = 0.750
compliance_component = 78 / 100                            = 0.780
release_component    = 0.5   (warn)
sca_component        = 1.0 - (0.30 + 0.40 + 0.16)         = 0.140
quality_component    = 0.60*0.4 + 0.50*0.2 + 0.90*0.2 + 0.65*0.2
                     = 0.240 + 0.100 + 0.180 + 0.130       = 0.650

Health Score:

= (0.750*0.30 + 0.780*0.25 + 0.5*0.20 + 0.140*0.15 + 0.650*0.10) * 100
= (0.225 + 0.195 + 0.100 + 0.021 + 0.065) * 100
= 0.606 * 100 = 60.6

Оценка: C — Уровень риска: medium (балл < 70 И статус ворот = warn)

Пример 3: Проект в зоне риска¶

Входные данные Значение
audit_score 4.0
compliance_pct 35%
release_status fail
sca_critical 5, sca_high
test_coverage 0.20, doc_coverage

Компоненты:

audit_component      = 4.0 / 10.0                          = 0.400
compliance_component = 35 / 100                            = 0.350
release_component    = 0.0   (fail)
sca_component        = max(0, 1.0 - (0.75 + 0.64 + 0.24)) = max(0, -0.63) = 0.000
quality_component    = 0.20*0.4 + 0.15*0.2 + 0.60*0.2 + 0.30*0.2
                     = 0.080 + 0.030 + 0.120 + 0.060       = 0.290

Health Score:

= (0.400*0.30 + 0.350*0.25 + 0.0*0.20 + 0.0*0.15 + 0.290*0.10) * 100
= (0.120 + 0.087 + 0.000 + 0.000 + 0.029) * 100
= 0.236 * 100 = 23.6

Оценка: F — Уровень риска: critical (балл < 40 И compliance_pct < 40% И sca_critical > 0)

Конфигурация¶

Все пороги и веса задаются в config.yaml в разделе dashboard:. Полный список параметров — в Справочнике конфигурации.
