Анализ потоков данных безопасности

Проследите путь данных к опасной операции. Выполните аудит проекта или анализ метода через MCP, затем проверьте вызовы и очистку данных.

РуководстваОбновлено: 2026-10-03

Анализ потоков данных помогает ответить на вопрос: как входные данные доходят до операции, которая выполняет SQL, запускает команду или записывает файл? CodeGraph ищет пути в CPG от источника данных к приёмнику и показывает вызовы, места в коде и найденные функции очистки.

Используйте результат при ревью обработки входных данных, аудите безопасности и проверке исправления: пройдите по найденному пути, изучите преобразования данных и сопоставьте их с условиями выполнения приложения.

Выберите способ анализа

Выберите способ анализа
Задача Способ анализа Что разбирать
Получить список замечаний по проекту Общий аудит с профилем deep_security Отчёт нескольких проверок и сведения об их выполнении.
Исследовать конкретный метод MCP-анализ по точному method_name Пути через метод, функции источника и приёмника.
Проверить обработку входных данных Ревью найденного пути Присваивания, вызовы, очистку данных и границы доверия.

Выполните общий аудит проекта

Установите CLI по руководству. Выполняйте пример в PowerShell из корня репозитория CodeGraph. Нужен доступный сервис GoCPG и актуальный CPG зарегистрированного проекта. CodeGraph использует связь проекта, базы и исходников для проверки свежести. Выберите базу этого проекта и новый файл отчёта:

$env:CODEGRAPH_ALLOW_LOCAL_PYTHON_CLI = '1'
python -m src.cli audit --db 'C:/analysis/project.duckdb' `
  --profile deep_security --skip-persistence --skip-llm-conclusion --language ru `
  --format json --output 'dataflow-audit.json'
if ($LASTEXITCODE -ne 0) { throw 'Audit failed' }
$report = Get-Content -Raw 'dataflow-audit.json' | ConvertFrom-Json

Отчёт сохраняется в текущем каталоге и перезаписывает одноимённый файл. Проверьте сообщения о свежести графа и полноте анализа. --skip-persistence отключает сохранение проекций аудита, снимков панели и истории команд; он не уменьшает область анализа. Сам файл отчёта сохраняется. --skip-llm-conclusion формирует отчёт без LLM-заключения. Для сводки с LLM настройте провайдера и уберите этот параметр. Разберите результаты и сведения о выполнении каждой проверки в отчёте.

При Could not resolve a configured project/source context выберите базу зарегистрированного проекта по руководству импорта. При устаревшем графе обновите CPG процессом проекта и повторите аудит.

Проверьте пути для метода через MCP

В активном профиле проверьте доступность и право вызова codegraph_security_taint_analysis_run. Инструмент требует method_name; значения по умолчанию — source_category="user_input" и sink_category="sql". Описанные категории источников: user_input, file_read, network, env; приёмников: sql, command, file_write, xss, buffer.

Текущий обработчик выбирает категорию анализа по sink_category, если он непустой, иначе по source_category. Источники выбираются по каталогу доменного плагина; source_category сохраняется в ответе как переданный аргумент. Затем обработчик отбирает найденные пути по точному имени метода среди пересечённых функций или функции источника/приёмника. Анализ ограничен настройками числа путей и времени до этого отбора. Для дальнейшего поиска проверьте точность имени метода, сведения о лимитах и выбранную категорию приёмников.

Вызов использует текущий контекст проекта и GoCPG gRPC. Не передавайте путь хранилища. Настройка описана в руководстве оператора MCP. Выберите нужный проект и вызовите codegraph_security_taint_analysis_run со следующими аргументами:

{
  "method_name": "<exact-method-name-from-your-CPG>",
  "source_category": "user_input",
  "sink_category": "sql"
}

Замените method_name точным именем из текущего графа. Это объект аргументов вызова MCP, а не REST-запрос или команда оболочки. Проверьте каждый возвращённый путь и его функции источника и приёмника. Используйте count как число возвращённых путей, а заключение по каждому пути запишите после проверки условий выполнения.

Ответ содержит method, переданные категории, taint_paths и count. Переданные категории отражаются в ответе; выбор анализа описан выше. При ответе Error: ... восстановите доступ к выбранному CPG по сообщению и повторите вызов.

Как читать путь

Как читать путь
Поле пути Действие проверяющего
source, sink Открыть указанные функции, файлы и строки; проверить вход и чувствительную операцию.
path, functions_crossed Разобрать последовательность функций между источником и приёмником.
sanitizers Проверить найденные функции очистки и применимость к данным приёмника.
risk_score, risk_level, confidence Выбрать порядок ревью по оценкам анализатора.
inter_procedural, tainted_fields Проверить переходы между функциями и отслеживаемые поля данных.

Проверьте находку

  1. Подтвердите, что источник контролируется атакующим в этих условиях выполнения.
  2. Проверьте каждый вызов и присваивание в найденном пути.
  3. Проверьте очистку и проверку данных, кодирование, авторизацию и границы доверия.
  4. Убедитесь, что приёмник достижим с указанной формой данных.
  5. Сохраните ревизию кода, категории, ссылки на доказательства и заключение проверяющего.

После разбора найденных путей продолжите ревью остальных источников, приёмников и границ среды исполнения приложения.

Источники контракта

  • src/mcp/tools/security_suite/security.py — MCP-инструмент анализа метода и контракт категорий;
  • src/analysis/dataflow/taint/propagator.py — распространение недоверенных данных;
  • src/analysis/dataflow/taint/models.py — структура пути данных;
  • src/cli/analysis_commands/audit_commands.py — подключение анализа к общему аудиту.
