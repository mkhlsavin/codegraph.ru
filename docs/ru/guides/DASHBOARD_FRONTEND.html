Руководство по разработке интерфейса панели управления

Руководство по разработке интерфейса панели управления¶

Панель управления CISO/CTO CodeGraph – одностраничное приложение на React 18, TypeScript, Vite, Recharts и D3. Она предоставляет оперативный обзор состояния кодовой базы: оценки аудита, статус соответствия стандартам, готовность к выпуску, уязвимости зависимостей и межрепозиторный анализ по всему портфелю проектов.

Приложение использует react-router-dom версии 6 с BrowserRouter:

/dashboard                -> Portfolio (главная)
/dashboard/red-zone       -> RedZone
/dashboard/compare        -> CompareCenter
/dashboard/projects       -> ProjectsCatalog

Все маршруты вложены в компонент разметки Shell, обеспечивающий боковую панель и навигационную цепочку.

Управление состоянием¶

Приложение использует два пользовательских перехватчика для управления состоянием. Глобальное хранилище отсутствует: все данные запрашиваются на уровне страницы и передаются дочерним компонентам через параметры.

Перехватчик useApi<T>¶

Расположение: src/hooks/useApi.ts

Обобщённый перехватчик загрузки данных, оборачивающий асинхронные вызовы API с состоянием загрузки, обработкой ошибок и возможностью повторного запроса.

function useApi<T>(fetcher: () => Promise<T>, deps: unknown[] = []): UseApiResult<T>

interface UseApiResult<T> {
  data: T | null;        // Данные ответа, null до загрузки
  loading: boolean;      // True во время загрузки
  error: string | null;  // Текст ошибки из catch, null при успехе
  refetch: () => void;   // Повторный вызов fetcher
}

Ключевые особенности: - Автоматический вызов fetcher при монтировании и изменении deps - Защита от обновления состояния размонтированных компонентов через mountedRef - Сброс error в null при каждом новом запросе

Пример использования:

const { data, loading, error } = useApi(
  () => api.projectHealth("my-project", { include_sections: true }),
  [projectName]
);

Перехватчик useWebSocket¶

Расположение: src/hooks/useWebSocket.ts

Управляет подключением WebSocket к API панели управления для получения уведомлений об обновлении проектов в реальном времени.

function useWebSocket(onProjectUpdated?: (name: string) => void): UseWebSocketResult

interface UseWebSocketResult {
  connected: boolean;          // Текущий статус подключения
  lastMessage: WsMessage | null; // Последнее полученное сообщение
}

interface WsMessage {
  event: string;
  project_name?: string;
  trigger?: string;
  timestamp?: number;
  client_id?: string;
  heartbeat_seconds?: number;
  clients?: number;
}

Ключевые особенности: - Подключается к ws[s]://<узел>/api/v2/dashboard/ws на основе протокола текущей страницы - Автоматическое переподключение через 5 секунд после разрыва соединения - Вызов обратной функции onProjectUpdated при получении события project_updated - Беззвучное игнорирование некорректных сообщений и ошибок подключения

Клиент API¶

Расположение: src/api/client.ts

Все вызовы API проходят через объект api. Базовый адрес: /api/v2/dashboard. Каждый метод возвращает типизированный Promise.

Инструкции по сборке¶

Предварительные требования¶

  • Node.js 18+ (рекомендуется LTS)
  • npm 9+

Разработка¶

cd frontend
npm install          # Установка зависимостей
npm run dev          # Запуск сервера разработки на http://localhost:3100

Сервер разработки проксирует запросы /api на http://localhost:8000 (серверная часть CodeGraph), поэтому для загрузки данных серверная часть должна быть запущена.

Сборка для эксплуатации¶

npm run build        # Проверка типов (tsc) + сборка (vite) -> dist/
npm run preview      # Предварительный просмотр сборки

Результат помещается в frontend/dist/. Сборка создаёт три раздельных фрагмента кода: - vendor – React, ReactDOM, react-router-dom - charts – Recharts - d3 – d3-force, d3-selection, d3-zoom

Карты исходного кода включены по умолчанию (см. vite.config.ts -> build.sourcemap: true).

Проверка кода и типов¶

npm run lint         # ESLint со строгими правилами (ноль предупреждений)
npm run typecheck    # Проверка типов TypeScript без генерации файлов

Развёртывание¶

Статическое развёртывание через Nginx¶

Соберите приложение и настройте отдачу каталога dist/. Все маршруты должны возвращать index.html для корректной работы клиентской маршрутизации.

Пример конфигурации Nginx:

server {
    listen 80;
    server_name dashboard.example.com;

    root /var/www/codegraph-dashboard/dist;
    index index.html;

    # Клиентская маршрутизация: все пути /dashboard -> index.html
    location /dashboard {
        try_files $uri $uri/ /index.html;
    }

    # Проксирование вызовов API на серверную часть CodeGraph
    location /api {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Проксирование WebSocket для уведомлений в реальном времени
    location /api/v2/dashboard/ws {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }

    # Кеширование статических ресурсов
    location ~* \.(js|css|svg|png|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}

Развёртывание через Docker¶

Пример многоэтапного Dockerfile:

# Этап 1: Сборка
FROM node:18-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# Этап 2: Отдача
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Сборка и запуск:

docker build -t codegraph-dashboard ./frontend
docker run -p 3100:80 codegraph-dashboard

Переменные окружения¶

Vite предоставляет переменные окружения с префиксом VITE_ клиентскому коду через import.meta.env.

Переменная Значение по умолчанию Описание
VITE_API_URL /api (проксируется в режиме разработки) Базовый адрес REST API
VITE_WS_URL Определяется автоматически из window.location Адрес WebSocket для уведомлений

Создайте файл .env в каталоге frontend/ для локальных переопределений:

VITE_API_URL=http://localhost:8000/api
VITE_WS_URL=ws://localhost:8000/api/v2/dashboard/ws

В рабочем режиме проксирование сервера разработки недоступно. Настройте Nginx (или другой обратный прокси) для перенаправления /api на серверную часть, либо задайте VITE_API_URL при сборке с указанием адреса сервера API.

Как добавить новую страницу¶

  1. Создайте компонент страницы в src/pages/:
// src/pages/MyNewPage.tsx
import { api } from "@/api/client";
import { useApi } from "@/hooks/useApi";
import { Loading, ErrorDisplay } from "@/components/ui/StatusIndicators";

export function MyNewPage() {
  const { data, loading, error } = useApi(() => api.portfolio(), []);

  if (loading) return <Loading />;
  if (error) return <ErrorDisplay message={error} />;
  if (!data) return null;

  return (
    <div className="page-enter">
      <h1 style={{ fontSize: 22, fontWeight: 700, letterSpacing: "-0.02em" }}>
        Новая страница
      </h1>
      {/* Содержимое страницы */}
    </div>
  );
}
  1. Добавьте маршрут в src/App.tsx:
import { MyNewPage } from "@/pages/MyNewPage";

// Внутри <Routes> -> <Route element={<Shell />}>:
<Route path="my-page" element={<MyNewPage />} />
  1. Добавьте ссылку в боковую панель в src/components/layout/Sidebar.tsx:
// Добавьте в массив NAV_ITEMS:
{ path: "/my-page", label: "Новая страница", icon: "grid" }
  1. Добавьте наименование в навигационную цепочку в src/components/layout/Breadcrumb.tsx:
// Добавьте в таблицу LABELS:
"my-page": "Новая страница",
  1. Проверьте: откройте http://localhost:3100/dashboard/my-page в браузере.

Как добавить новый компонент графика¶

  1. Создайте компонент в src/components/charts/:
// src/components/charts/MyChart.tsx
import {
  BarChart,
  Bar,
  XAxis,
  YAxis,
  CartesianGrid,
  Tooltip,
  ResponsiveContainer,
} from "recharts";

interface Props {
  data: { name: string; value: number }[];
  height?: number;
}

export function MyChart({ data, height = 280 }: Props) {
  if (data.length === 0) {
    return (
      <div style={{ textAlign: "center", color: "var(--cg-text-muted)", padding: 40, fontSize: 13 }}>
        Нет данных
      </div>
    );
  }

  return (
    <ResponsiveContainer width="100%" height={height}>
      <BarChart data={data} margin={{ top: 8, right: 16, bottom: 8, left: 0 }}>
        <CartesianGrid strokeDasharray="3 3" stroke="var(--cg-border)" />
        <XAxis
          dataKey="name"
          tick={{ fill: "var(--cg-text-muted)", fontSize: 10 }}
          tickLine={false}
          axisLine={{ stroke: "var(--cg-border)" }}
        />
        <YAxis
          tick={{ fill: "var(--cg-text-muted)", fontSize: 10 }}
          tickLine={false}
          axisLine={false}
          width={40}
        />
        <Tooltip
          contentStyle={{
            background: "var(--cg-surface)",
            border: "1px solid var(--cg-border)",
            borderRadius: 6,
            fontSize: 12,
            fontFamily: "var(--cg-font)",
          }}
        />
        <Bar dataKey="value" fill="var(--cg-primary)" radius={[4, 4, 0, 0]} />
      </BarChart>
    </ResponsiveContainer>
  );
}

  1. Соблюдайте соглашения: - Всегда оборачивайте график в <ResponsiveContainer> для адаптивной ширины - Возвращайте текст-заглушку при пустом массиве data - Используйте пользовательские CSS-свойства (var(--cg-*)) для всех цветов и шрифтов, чтобы учитывать тему оформления - Оформляйте всплывающие подсказки единообразно: background: var(--cg-surface), border: 1px solid var(--cg-border), borderRadius: 6, fontSize: 12 - Цвета критичности: критический #EF4444, высокий #F59E0B, средний #EAB308, низкий #10B981

  2. Подключите и используйте в компоненте страницы:

import { MyChart } from "@/components/charts/MyChart";

// Внутри JSX:
<div className="card">
  <div className="card-header">
    <span className="card-title">Заголовок графика</span>
  </div>
  <MyChart data={chartData} />
</div>

Тестирование¶

Модульные тесты (Vitest)¶

Проект использует Vitest в качестве среды тестирования. Конфигурация наследуется из vite.config.ts.

npm run test           # Запуск всех тестов однократно
npm run test:watch     # Запуск тестов в режиме наблюдения

При написании тестов размещайте их рядом с исходным файлом или в каталоге __tests__/:

// src/components/ui/__tests__/StatusIndicators.test.tsx
import { render, screen } from "@testing-library/react";
import { GradeBadge } from "../StatusIndicators";

test("отображает метку оценки с правильным текстом", () => {
  render(<GradeBadge grade="A" />);
  expect(screen.getByText("A")).toBeInTheDocument();
  expect(screen.getByLabelText("Grade A")).toBeInTheDocument();
});

Сквозные тесты (Playwright)¶

Для сквозного тестирования используется Playwright для проверки полных сценариев страниц:

npx playwright install     # Установка браузеров (при первом запуске)
npx playwright test        # Запуск сквозных тестов

Типичная структура теста:

// e2e/portfolio.spec.ts
import { test, expect } from "@playwright/test";

test("главная страница загружается и отображает карточки показателей", async ({ page }) => {
  await page.goto("/dashboard");
  await expect(page.locator("h1")).toContainText("Portfolio Overview");
  await expect(page.locator(".stat-value").first()).toBeVisible();
});

Переключение темы¶

Тема определяется атрибутом data-theme на элементе <html>:

  • При загрузке страницы main.tsx считывает localStorage.getItem("cg-theme") и восстанавливает значение; при отсутствии используется системная настройка через prefers-color-scheme
  • Кнопка переключения темы в боковой панели чередует "dark" и "light", сохраняя выбор в localStorage
  • Значение по умолчанию в index.html: data-theme="dark"

Переходы¶

Все интерактивные элементы используют --cg-transition: 180ms cubic-bezier(0.16, 1, 0.3, 1) для плавного изменения состояний. Переходы страниц используют анимацию pageIn (прозрачность + смещение по вертикали за 350 мс).
