Руководство по эксплуатации дашборда

Этот документ нужен тем, кто отвечает за рабочее состояние дашборда.

Дашборд полезен только тогда, когда полезны сигналы под ним.

Что здесь на самом деле значит эксплуатация¶

Эксплуатировать дашборд — значит поддерживать в хорошем состоянии четыре слоя:

  • API;
  • GoCPG;
  • OpenViking;
  • PostgreSQL.

Если один из них работает плохо, дашборд всё ещё может открываться, но показывать только часть правды.

Что нужно контролировать в первую очередь¶

Сначала нужно смотреть на:

  • здоровье API дашборда;
  • отставание синхронизации проектов;
  • доступность OpenViking;
  • состояние базы управления доступом и жизненным циклом;
  • свежесть снимков и сводок, которые видят пользователи.

Главное правило¶

Нельзя считать дашборд здоровым только потому, что страница открывается.

Он здоров только тогда, когда сигналы под ним актуальны и заслуживают доверия.

Эксплуатация уведомлений¶

Минимальный путь оператора для контура уведомлений такой:

  • выполнить codegraph dashboard notifications bootstrap
  • убедиться, что выбран реальный проект с живыми данными
  • помнить, что test deliveries не равны evidence живого pipeline

Это важно, потому что тестовая отправка может пройти успешно, а реальная страница всё ещё останется пустой.

Эксплуатация портфеля¶

Для портфельного режима нужно явно контролировать две вещи:

  • исторический маршрут сравнения: POST /api/v2/dashboard/portfolio/compare-periods
  • сохранённые представления, то есть saved view, которые должны оставаться воспроизводимыми перед сравнением и экспортом

Так сохраняется единое поведение между Web, REST, CLI и MCP.
