Плагин CodeGraph для OpenCode

Плагин CodeGraph для OpenCode¶

Плагин OpenCode, обеспечивающий автоматический анализ кода на основе CPG непосредственно в AI-ассистенте OpenCode.

Обзор¶

Плагин opencode-codegraph интегрирует анализ графа свойств кода (CPG) CodeGraph в OpenCode. Он автоматически обогащает диалоги с ИИ данными CPG – результатами анализа безопасности, графами вызовов, метриками сложности и анализом распространения данных (taint analysis) – без необходимости вручную вызывать инструменты.

Три уровня интеграции работают совместно:

Уровень Назначение Механизм работы
MCP-инструменты (25+) Прямые CPG-запросы codegraph_query, codegraph_explain и др.
LSP-сервер Диагностика в реальном времени Результаты безопасности, мёртвый код, сложность в редакторе
Плагин (этот документ) Автоматическое обогащение контекста Внедрение CPG-контекста в чат, обновления после коммитов

Установка¶

Из npm¶

bun install opencode-codegraph

В opencode.json¶

{
  "plugin": ["opencode-codegraph"],
  "mcp": {
    "codegraph": {
      "type": "local",
      "command": ["python", "-m", "src.mcp", "--transport", "stdio"]
    }
  },
  "lsp": {
    "codegraph": {
      "command": ["python", "-m", "codegraph_lsp", "--db", "project.duckdb"],
      "languages": ["python", "go", "javascript", "typescript", "java", "c", "cpp"]
    }
  }
}

Предварительные требования¶

  • CodeGraph установлен (pip install -e . в репозитории codegraph)
  • CPG-база данных создана (gocpg parse --input=. --output=project.duckdb)
  • API CodeGraph запущен (uvicorn src.api.main:app --port 8000) – требуется для автоматического обогащения контекста плагином

Функции¶

1. Автоматическое обогащение контекста данными CPG¶

Когда вы упоминаете файл в чате, плагин автоматически добавляет данные CPG:

You: "Refactor src/api/routers/webhook.py"

Plugin auto-injects:
  ### CPG context: src/api/routers/webhook.py
  **12 methods** in file:
  - `receive_github_webhook` CC=5 fan_in=0 fan_out=3 [entry]
  - `_handle_push` CC=2 fan_in=4 fan_out=2
  ...
  **2 security findings:**
  - CWE-89 L42: SQL injection in query parameter

LLM видит этот контекст и может принимать обоснованные решения о коде.

2. Системный промпт со сводкой по проекту¶

Каждый диалог включает сводку CPG-проекта:

## CodeGraph CPG Context
- **Files**: 450
- **Methods**: 12000
- **Security findings**: 8

### Top complex methods
- `process_audit_results` (CC=35, fan_in=12)
- `_build_composite_response` (CC=28, fan_in=8)

3. Обновление CPG после коммитов¶

После git commit плагин запускает инкрементальное обновление CPG:

  1. Обнаруживает коммит в хуке tool.execute.after
  2. Отправляет запрос на обновление в API CodeGraph
  3. GoCPG повторно разбирает изменённые файлы
  4. ChromaDB синхронизирует векторное хранилище
  5. LSP-сервер автоматически подхватывает новые данные

4. Пользовательские инструменты¶

Два инструмента плагина доступны наряду с MCP-инструментами:

Инструмент Описание
codegraph_review Анализ безопасности и влияния изменений на текущий diff
codegraph_explain_function Глубокий анализ функции с графом вызовов

5. Автоматические разрешения¶

Все инструменты codegraph_* автоматически разрешаются через хук permission.ask. Подтверждение для CPG-запросов не требуется.

Пользовательские команды¶

Четыре команды доступны через /command в OpenCode:

Команда Описание Использование
/review Анализ кода на основе CPG /review HEAD~3
/audit Полный аудит кодовой базы (12 измерений) /audit
/explain Анализ функции с графом вызовов /explain process_data
/onboard Изучение кодовой базы /onboard или /onboard how does auth work?

Команды определены в .opencode/commands/ как файлы markdown с YAML-заголовком (frontmatter).

Пользовательский агент¶

Переключитесь на агент CodeGraph для анализа на основе CPG:

/agent codegraph

Агент codegraph: - Всегда проверяет CPG перед изменением кода - Проверяет вызывающие функции перед рефакторингом - Запускает анализ распространения данных перед проверкой безопасности - Расставляет приоритеты по метрикам сложности и влияния - Использует модель claude-sonnet-4-6

Определён в .opencode/agents/codegraph.md.

Конфигурация¶

Переменные окружения¶

Переменная Значение по умолчанию Описание
CODEGRAPH_API_URL http://localhost:8000 Базовый URL API CodeGraph
CODEGRAPH_PROJECT (пусто) Идентификатор проекта по умолчанию

Структура плагина¶

opencode-codegraph/
  src/
    index.ts      # Plugin entry point (hooks)
    api.ts        # CodeGraph REST API client
    util.ts       # File ref extraction, git commit detection
  package.json
  tsconfig.json

.opencode/
  commands/
    review.md     # /review command
    audit.md      # /audit command
    explain.md    # /explain command
    onboard.md    # /onboard command
  agents/
    codegraph.md  # codegraph agent

Архитектура¶

OpenCode
  |
  +-- Plugin (opencode-codegraph)
  |     |-- chat.message hook        --> CodeGraph REST API --> CPG context
  |     |-- system.transform hook    --> CodeGraph REST API --> project summary
  |     |-- tool.execute.after hook  --> CodeGraph REST API --> incremental update
  |     |-- permission.ask hook      --> auto-allow codegraph_*
  |     +-- custom tools             --> CodeGraph REST API --> review/explain
  |
  +-- MCP Server (src.mcp)
  |     +-- 25 tools                 --> CPG queries, taint analysis, audit
  |
  +-- LSP Server (codegraph_lsp)
        +-- diagnostics              --> security, dead code, complexity
        +-- hover                    --> method metrics
        +-- codelens                 --> callers/callees/taint
        +-- codeaction               --> autofix

Устранение неполадок¶

Плагин не загружается¶

  • Проверьте, что в opencode.json указано "plugin": ["opencode-codegraph"]
  • Убедитесь, что пакет установлен: bun list opencode-codegraph
  • Проверьте журналы OpenCode на наличие ошибок загрузки плагина

CPG-контекст не появляется в чате¶

  • Убедитесь, что API CodeGraph запущен: curl http://localhost:8000/api/v1/health
  • Проверьте переменную окружения CODEGRAPH_API_URL
  • Убедитесь, что CPG-база данных создана и содержит данные

Команды недоступны¶

  • Убедитесь, что каталог .opencode/commands/ существует в корне проекта
  • Проверьте, что файлы содержат корректный YAML-заголовок (начинается с ---)
  • Перезапустите OpenCode после добавления новых команд

Агент не отображается¶

  • Убедитесь, что файл .opencode/agents/codegraph.md существует
  • Проверьте, что YAML-заголовок содержит обязательные поля (description, model)
  • Перезапустите OpenCode после добавления файла агента

Обновления после коммитов не работают¶

  • Убедитесь, что API CodeGraph запущен с включёнными эндпоинтами вебхуков
  • Проверьте, что CODEGRAPH_PROJECT указывает на правильный идентификатор проекта
  • Проверьте эндпоинт вебхука: curl http://localhost:8000/api/v1/webhooks/status/{project_id}
