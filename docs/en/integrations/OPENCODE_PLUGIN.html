CodeGraph OpenCode Plugin

CodeGraph OpenCode Plugin¶

OpenCode plugin that provides automatic CPG-powered code intelligence directly in the OpenCode AI coding assistant.

Table of Contents¶

  • Overview

  • Features
  • Custom Commands
  • Custom Agent

  • Architecture

Overview¶

The opencode-codegraph plugin integrates CodeGraph’s Code Property Graph (CPG) analysis into OpenCode. It automatically enriches AI conversations with CPG data – security findings, call graphs, complexity metrics, and taint analysis – without requiring manual tool invocation.

Three integration layers work together:

Layer What it does How it works
MCP Tools (25+) Direct CPG queries codegraph_query, codegraph_explain, etc.
LSP Server Real-time diagnostics Security findings, dead code, complexity in editor
Plugin (this) Auto-enrichment Injects CPG context into chat, post-commit updates

Installation¶

From npm¶

bun install opencode-codegraph

In opencode.json¶

{
  "plugin": ["opencode-codegraph"],
  "mcp": {
    "codegraph": {
      "type": "local",
      "command": ["python", "-m", "src.mcp", "--transport", "stdio"]
    }
  },
  "lsp": {
    "codegraph": {
      "command": ["python", "-m", "codegraph_lsp", "--db", "project.duckdb"],
      "languages": ["python", "go", "javascript", "typescript", "java", "c", "cpp"]
    }
  }
}

Prerequisites¶

  • CodeGraph installed (pip install -e . in the codegraph repo)
  • CPG database built (gocpg parse --input=. --output=project.duckdb)
  • CodeGraph API running (uvicorn src.api.main:app --port 8000) – required for plugin auto-enrichment

Features¶

1. Automatic CPG Context Enrichment¶

When you mention a file in chat, the plugin automatically adds CPG data:

You: "Refactor src/api/routers/webhook.py"

Plugin auto-injects:
  ### CPG context: src/api/routers/webhook.py
  **12 methods** in file:
  - `receive_github_webhook` CC=5 fan_in=0 fan_out=3 [entry]
  - `_handle_push` CC=2 fan_in=4 fan_out=2
  ...
  **2 security findings:**
  - CWE-89 L42: SQL injection in query parameter

The LLM sees this context and can make informed decisions about the code.

2. System Prompt with Project Summary¶

Every conversation includes a CPG project summary:

## CodeGraph CPG Context
- **Files**: 450
- **Methods**: 12000
- **Security findings**: 8

### Top complex methods
- `process_audit_results` (CC=35, fan_in=12)
- `_build_composite_response` (CC=28, fan_in=8)

3. Post-Commit CPG Updates¶

After a git commit, the plugin triggers an incremental CPG update:

  1. Detects commit in tool.execute.after hook
  2. Sends update request to CodeGraph API
  3. GoCPG re-parses changed files
  4. ChromaDB vector store syncs
  5. LSP server picks up new data automatically

4. Custom Tools¶

Two plugin tools are available alongside MCP tools:

Tool Description
codegraph_review Security + impact analysis on current diff
codegraph_explain_function Deep function analysis with call graph

5. Auto-Permissions¶

All codegraph_* tools are auto-allowed via the permission.ask hook. No confirmation prompts for CPG queries.

Custom Commands¶

Four commands are available via /command in OpenCode:

Command Description Usage
/review CPG-powered code review /review HEAD~3
/audit Full codebase audit (12 dimensions) /audit
/explain Function analysis with call graph /explain process_data
/onboard Codebase understanding /onboard or /onboard how does auth work?

Commands are defined in .opencode/commands/ as markdown files with YAML frontmatter.

Custom Agent¶

Switch to the CodeGraph agent for CPG-focused analysis:

/agent codegraph

The codegraph agent: - Always checks CPG before modifying code - Verifies callers before refactoring - Runs taint analysis before security reviews - Prioritizes by complexity and impact metrics - Uses claude-sonnet-4-6 model

Defined in .opencode/agents/codegraph.md.

Configuration¶

Environment Variables¶

Variable Default Description
CODEGRAPH_API_URL http://localhost:8000 CodeGraph API base URL
CODEGRAPH_PROJECT (empty) Default project ID

Plugin Structure¶

opencode-codegraph/
  src/
    index.ts      # Plugin entry point (hooks)
    api.ts        # CodeGraph REST API client
    util.ts       # File ref extraction, git commit detection
  package.json
  tsconfig.json

.opencode/
  commands/
    review.md     # /review command
    audit.md      # /audit command
    explain.md    # /explain command
    onboard.md    # /onboard command
  agents/
    codegraph.md  # codegraph agent

Architecture¶

OpenCode
  |
  +-- Plugin (opencode-codegraph)
  |     |-- chat.message hook        --> CodeGraph REST API --> CPG context
  |     |-- system.transform hook    --> CodeGraph REST API --> project summary
  |     |-- tool.execute.after hook  --> CodeGraph REST API --> incremental update
  |     |-- permission.ask hook      --> auto-allow codegraph_*
  |     +-- custom tools             --> CodeGraph REST API --> review/explain
  |
  +-- MCP Server (src.mcp)
  |     +-- 25 tools                 --> CPG queries, taint analysis, audit
  |
  +-- LSP Server (codegraph_lsp)
        +-- diagnostics              --> security, dead code, complexity
        +-- hover                    --> method metrics
        +-- codelens                 --> callers/callees/taint
        +-- codeaction               --> autofix

Troubleshooting¶

Plugin Not Loading¶

  • Check opencode.json has "plugin": ["opencode-codegraph"]
  • Verify the package is installed: bun list opencode-codegraph
  • Check OpenCode logs for plugin loading errors

No CPG Context in Chat¶

  • Verify CodeGraph API is running: curl http://localhost:8000/api/v1/health
  • Check CODEGRAPH_API_URL environment variable
  • Ensure CPG database is built and has data

Commands Not Available¶

  • Verify .opencode/commands/ directory exists in project root
  • Check files have valid YAML frontmatter (starts with ---)
  • Restart OpenCode after adding new commands

Agent Not Showing¶

  • Verify .opencode/agents/codegraph.md exists
  • Check frontmatter has required fields (description, model)
  • Restart OpenCode after adding the agent file

Post-Commit Updates Not Working¶

  • Ensure CodeGraph API is running with webhook endpoints enabled
  • Check that CODEGRAPH_PROJECT is set to the correct project ID
  • Verify the webhook endpoint: curl http://localhost:8000/api/v1/webhooks/status/{project_id}
