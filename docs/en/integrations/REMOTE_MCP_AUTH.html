Remote MCP authentication

Install a CodeGraph client plugin, connect MCP, and authorize Codex, VS Code, Cursor, GitHub Copilot, or OpenCode for your instance.

IntegrationsUpdated: 2026-09-24

Use the portable Agent Plugins package supplied by the operator for the hosted CodeGraph service. It targets Agent Plugins 1.0.0 and contains one fixed Streamable HTTP URL. It does not contain a token, API key, OAuth client secret, credential reference, stdio command, SSE endpoint, or fallback.

The package format deliberately has no OAuth fields. The client receives a 401 Bearer challenge, discovers CodeGraph authorization metadata, registers a public client, opens the browser, uses S256 PKCE, and stores the resulting credentials in its own secure store. This is different from the native Codex package, which is a separate artifact using trusted stdio.

Client for an internal server

If CodeGraph runs in your organization’s network, first sign in and get project access. Ask the administrator for the SSH host and login, absolute path of the client distribution, Codex and Agent Plugins archive names, UI and API URLs, MCP address, and tunnel parameters if needed. The client package must match the server version. Run the commands below on your workstation. Install Codex through an approved channel and check codex --version.

Windows PowerShell (requires ssh and scp):

Set-Location "$env:USERPROFILE\Downloads"
scp -r -o 'User=<SSH_LOGIN>' '<SSH_HOST>:<DISTRIBUTION_PATH>' .
Set-Location '.\<DISTRIBUTION_DIRECTORY>'
Get-Content .\SHA256SUMS | ForEach-Object {
  $expected,$name=$_ -split '\s+',2
  if ((Get-FileHash -LiteralPath $name.Trim() -Algorithm SHA256).Hash -ne $expected) { throw "SHA-256 mismatch: $name" }
}
Expand-Archive '.\<CODEX_PLUGIN_ARCHIVE.zip>' -DestinationPath .\codex-plugin
$env:CODEX_HOME="$env:USERPROFILE\.codex-codegraph\my-project"
New-Item -ItemType Directory -Force $env:CODEX_HOME | Out-Null
codex login
codex plugin marketplace add .\codex-plugin --json
codex plugin add 'codegraph@<MARKETPLACE_NAME>' --json
codex mcp get codegraph --json

macOS or Ubuntu, Bash (requires ssh, scp, unzip, and Python 3):

cd "$HOME/Downloads"
scp -r -o 'User=<SSH_LOGIN>' '<SSH_HOST>:<DISTRIBUTION_PATH>' .
cd '<DISTRIBUTION_DIRECTORY>'
if [ "$(uname -s)" = Darwin ]; then shasum -a 256 -c SHA256SUMS; else sha256sum -c SHA256SUMS; fi
mkdir -p codex-plugin
unzip '<CODEX_PLUGIN_ARCHIVE.zip>' -d codex-plugin
export CODEX_HOME="$HOME/.codex-codegraph/my-project"
mkdir -p "$CODEX_HOME"
codex login
codex plugin marketplace add ./codex-plugin --json
codex plugin add 'codegraph@<MARKETPLACE_NAME>' --json
codex mcp get codegraph --json

Replace angle-bracket parameters with your distribution values; the marketplace name is in the package manifest. Use one CODEX_HOME for installation and working sessions. codex login authorizes Codex itself; CodeGraph requires a separate sign-in. If MCP only listens on the server loopback address, keep this tunnel open in a separate terminal:

ssh -N -L <LOCAL_PORT>:127.0.0.1:<SERVER_MCP_PORT> -l '<SSH_LOGIN>' <SSH_HOST>

Match the local URL in mcp.json to the tunnel port. For direct HTTPS access, use the address and sign-in mechanism configured by the administrator. For a distribution using a personal Bearer token, call POST <API_URL>/api/v1/auth/token with {"username":"<personal-login>","password":"<personal-password>"}. The REST schemas are at <API_URL>/api/docs and <API_URL>/api/openapi.json. If the package expects CODEGRAPH_MCP_TOKEN, set it to the returned access_token in the same terminal that starts Codex. Do not write the token to your project or config.toml.

Windows PowerShell:

$api='<API_URL>/api/v1'
$credential=Get-Credential
$body=@{username=$credential.UserName;password=$credential.GetNetworkCredential().Password} | ConvertTo-Json
$env:CODEGRAPH_MCP_TOKEN=(Invoke-RestMethod -Method Post -Uri "$api/auth/token" -ContentType 'application/json' -Body $body).access_token

macOS or Ubuntu, Bash:

export CODEGRAPH_API_URL='<API_URL>'
export CODEGRAPH_MCP_TOKEN="$(python3 - <<'PY'
import getpass
import json
import os
import sys
import urllib.request

sys.stderr.write('CodeGraph login: ')
with open('/dev/tty', encoding='utf-8') as terminal:
    username = terminal.readline().rstrip('\n')
password = getpass.getpass('CodeGraph password: ')
body = json.dumps({'username': username, 'password': password}).encode()
request = urllib.request.Request(
    os.environ['CODEGRAPH_API_URL'] + '/api/v1/auth/token',
    data=body,
    headers={'Content-Type': 'application/json'},
    method='POST',
)
with urllib.request.urlopen(request, timeout=15) as response:
    print(json.load(response)['access_token'])
PY
)"

Open your local project checkout and start codex. Confirm access by calling codegraph_runtime_stack_status_get with empty arguments. The MCP request is:

{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"codegraph_runtime_stack_status_get","arguments":{}}}

Then call codegraph_project_context_status and codegraph_project_context_sync_status with {} and check the selected project. For another Agent Plugins client, extract <AGENT_PLUGIN_ARCHIVE.zip> and install it as a local plugin through that client’s UI. The client must support Streamable HTTP MCP and send the personal token. Keep the existing rules in your project’s AGENTS.md and point it to your repository’s documentation directory; review the packaged template before copying it.

Before login

  1. Install or import the supplied portable package using the client’s Agent Plugin UI, marketplace, or local-plugin setting.
  2. Confirm that the discovered server is named codegraph and its URL is https://api.codegraph.ru/agent-plugin/mcp.
  3. Know the unique project name you are allowed to use. Enter that human-readable name in the browser consent form. A project UUID is also accepted and is required when names are ambiguous. The form binds the token to the canonical project UUID; changing X-Project-ID cannot widen access. The standalone consent page uses the same visual tokens and form hierarchy as the CodeGraph frontend login page; verify the CodeGraph CG mark and the client name before entering credentials.
  4. Review the requested scopes: mcp:tools and mcp:project.

Codex CLI and IDE extension

If the portable plugin is not installed from a marketplace, register the same secret-free remote entry directly. Use lowercase dcr; it is the CLI enum value:

codex mcp add codegraph --url https://api.codegraph.ru/agent-plugin/mcp --oauth-resource https://api.codegraph.ru/agent-plugin/mcp --oauth-client-registration dcr

Then run, or rerun after the initial flow:

codex mcp login codegraph

Complete the CodeGraph login, enter the authorized unique project name or project UUID, approve the two MCP scopes, and return to Codex. Verify the connection with codex mcp list or /mcp, then ask Codex to call a read-only CodeGraph project-context tool. To clear the stored OAuth credential, run codex mcp logout codegraph; run the login command again to change account or recover after revocation. Do not put an access token in the plugin package or config.toml.

In the Codex IDE extension, open MCP servers, select codegraph, and choose Authenticate. The CLI and IDE extension share the same Codex MCP configuration.

VS Code with GitHub Copilot

Enable Agent Plugins (chat.plugins.enabled), install the package through the Agent Plugins view, Chat: Install Plugin From Source, or a trusted chat.pluginLocations entry, then run MCP: List Servers from the Command Palette and start codegraph. VS Code opens the browser automatically when the server returns the OAuth challenge. Sign in, enter the unique project name or project UUID, and approve the scopes. After redirect, confirm that the server is connected and invoke one read-only CodeGraph tool from Agent mode.

Use Accounts > Manage Trusted MCP Servers to review trust. Use Authentication: Remove Dynamic Authentication Providers to remove a DCR registration, then reconnect to authenticate again. CodeGraph validates the exact registered callback, with only the RFC 8252 loopback-port exception; do not preconfigure or copy callback URLs between machines.

Cursor editor and CLI

After installing the package or configuring the same remote server in Cursor, start authentication from the MCP server panel. In Cursor CLI, run:

cursor-agent mcp login codegraph

agent is an installed alias of cursor-agent, but the documented command is portable across Cursor CLI installations. Complete the browser flow, then check cursor-agent mcp list and cursor-agent mcp list-tools codegraph. Disable and re-enable the server to test reconnect. If the token was revoked or expired, rerun the login command; do not copy a token into .cursor/mcp.json. CodeGraph accepts Cursor’s exact RFC 8252 private-use registration callback cursor://anysphere.cursor-mcp/oauth/callback; arbitrary custom schemes, hosts and paths are rejected.

GitHub Copilot CLI

Install the Agent Plugin from a registered marketplace or your operator’s local package. You can also add the remote server through Copilot’s MCP management UI. In the interactive CLI, inspect it with /mcp list, then run:

/mcp auth codegraph

Complete browser authorization and verify one read-only project-scoped call. If status becomes needs-auth, run the same command again. Headless client_credentials is not part of the portable human-login package; automation must use the separately administered CodeGraph API-key or service- account contract and an operating-system keychain or secret manager.

OpenCode adapter scope

OpenCode is not listed in the Agent Plugins compatible-client registry, so do not claim that it loads this portable package. Configure the same remote MCP URL in opencode.json instead:

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "codegraph": {
      "type": "remote",
      "url": "https://api.codegraph.ru/agent-plugin/mcp"
    }
  }
}

Then run opencode mcp auth codegraph (or select CodeGraph under /connect), check opencode mcp list, and remove credentials with opencode mcp logout codegraph. OpenCode owns its OAuth credential store; the repository and portable package must remain secret-free.

Machine access

Interactive users should use OAuth. For CI or a headless operator, create a bounded CodeGraph API key or service account and configure it only in the client’s private MCP settings. A machine request needs X-API-Key, X-Project-ID, and X-CodeGraph-Machine-Contract: 2026-03-v1. Keep all three values outside plugin.json and mcp.json.

Codex can map private environment variables with env_http_headers. VS Code can use a secure input in user-level MCP configuration. Cursor and Copilot CLI should use their private credential store, keychain, or secret-manager integration. Agent Plugins headers are visible package data and must not contain these values. CodeGraph does not repair an OAuth failure by trying a machine key.

Failure and recovery

  • 401 with resource_metadata: no valid credential; use the client’s native login action.
  • 401 invalid_token: expired, revoked, wrong-issuer, wrong-audience, or wrong-resource token; remove the stored credential and authenticate again.
  • 403: the identity lacks a required scope or project membership; request access instead of editing a project header.
  • Browser redirect rejected: remove the dynamic registration and retry. CodeGraph accepts HTTPS, exact loopback HTTP redirects with the RFC 8252 ephemeral-port exception, and the exact Cursor callback named above; S256 PKCE is mandatory.
  • Server unavailable: stop. Remote mode never falls back to stdio, SSE, or unauthenticated MCP.
