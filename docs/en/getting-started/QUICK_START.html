Quick start

Sign in to a deployed CodeGraph instance, grant project access, import a repository, check its CPG, and connect a local MCP client.

Getting StartedUpdated: 2026-09-24

Use this path after an administrator has deployed CodeGraph and given you the UI and API URLs, an account, and project-group access. For a new server, follow the installation guide first. Replace <UI_URL> and <API_URL> with your own instance addresses; the API URL does not include /api/v1.

1. Check that the instance is ready

Sign in at <UI_URL>/dashboard/login; the project catalog is at <UI_URL>/dashboard/projects. Check <API_URL>/api/v1/health/ready. The REST schema is at <API_URL>/api/docs (Swagger UI) or <API_URL>/api/openapi.json (OpenAPI JSON).

If you need an account, the administrator first obtains a token from POST /api/v1/auth/token with username and password, then finds an existing group ID using GET /api/v1/groups. With Authorization: Bearer <admin-access-token>, create the user at POST /api/v1/admin/identity/users:

{
  "username": "engineer.one",
  "role": "analyst",
  "tenant_id": "<GROUP_ID_FROM_GET_GROUPS>",
  "change_reason": "Create a personal engineering account"
}

tenant_id records the audit context; it does not grant group access. Give the returned temporary_password to the user through a secure channel. analyst suits most developers; reviewer has additional review and approval permissions. viewer is read oriented and admin administers the instance. After importing a project, use its id from GET /api/v1/projects to grant access with PUT /api/v1/admin/identity/users/{user_id}/access:

{
  "tenant_id": "<GROUP_ID_FROM_GET_GROUPS>",
  "change_reason": "Grant access to the selected project",
  "assignments": [{
    "group_id": "<GROUP_ID_FROM_GET_GROUPS>",
    "role": "editor",
    "project_scope_mode": "selected",
    "allowed_project_ids": ["<PROJECT_ID_FROM_GET_PROJECTS>"]
  }]
}

editor is a group role, distinct from the system role. Group roles are viewer, editor, and admin. The PUT replaces all assignments: before changing an existing user, read GET /api/v1/admin/identity/users/{user_id}/access and retain the required entries.

2. Select or import a project

Open <UI_URL>/dashboard/repositories, select a configured Git provider, and import a repository. Then check <UI_URL>/dashboard/projects. If no provider is configured, follow the REST and server CLI examples. Do not put credentials in the repository URL.

CPG (Code Property Graph) records code elements and their relationships. A project listing does not prove the graph is ready. Check the import job and CPG freshness first; refresh a stale, pending, or failed graph before relying on the analysis.

3. Run a first task

For the first audit, an administrator connects to the Ubuntu server over SSH, changes to the CodeGraph installation directory, and runs the command below. Get the CPG database path from the configured project; the API container must see the source path. This produces a deterministic JSON report without an LLM conclusion:

sudo docker compose -f docker-compose.yml exec -T api python -m src.cli audit \
  --db '<CPG_DB_PATH>' --source-path '<PROJECT_SOURCE_PATH>' \
  --profile standard --format json --skip-llm-conclusion --skip-persistence \
  --output '<AUDIT_OUTPUT_PATH>'

Check the report, source revision, and analysis limitations. See the CPG audit guide for interpretation. Then choose a task with an observable result, for example:

  • find the entry points for a component;
  • inspect the impact of changing a named symbol;
  • review a bounded commit range;
  • explain a dependency path and cite its source locations.

Keep the first scope small. Confirm that the response names the selected project, includes source evidence, and states any freshness or availability limitation. A professional engineering or security decision still requires human review.

4. Connect a client and your project documentation

Install Codex CLI or an Agent Plugins compatible client on Windows, macOS, or Ubuntu. Get the MCP address and client package from your instance administrator. For the published remote service, follow the OAuth and MCP guide. After sign-in, call the read-only codegraph_runtime_stack_status_get tool with empty arguments:

{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"codegraph_runtime_stack_status_get","arguments":{}}}

Open a local checkout of the selected project. Its AGENTS.md should point to the actual documentation location. A useful starting layout is README.md for purpose and setup, and docs/ for architecture, API, operations, and checks. If your team uses OpenSpec, point to its existing specifications directory. For a small fix, create a named lightweight task with an owner, scope, and completion criterion. For a feature, prepare requirements and acceptance criteria in a full task under your team’s process.

5. Explore the bundled demo

To see a guided workflow without importing customer documents, open /dashboard/onboarding-research and select a demo preset. Demo data explains the interface; use the imported project and its current CPG for repository-specific results.

If the first run fails

  • No project is visible: ask the administrator to check tenant and project access.
  • CPG is stale or missing: request or wait for project refresh before repeating the analysis.
  • The result is blocked: preserve the reason and session identifier for support.
  • The result lacks source evidence: narrow the question and verify the selected project.

Contract sources

  • src/api/main.py — assembled API application and /health surface;
  • frontend/src/App.tsx — registered dashboard routes;
  • src/api/routers/projects.py — project operations;
  • src/services/cpg/ — project graph lifecycle and freshness behavior.
