Integrate CodeGraph security events with SIEM

Configure Syslog, CEF or LEEF event handlers. Verify dispatch, in-memory buffering, failure recovery and receipt at the downstream SIEM.

EnterpriseUpdated: 2026-10-03

CodeGraph sends security events to the system your SOC already uses. Authentication, LLM activity and DLP actions enter the same investigation stream. The request_id field connects an event to its request. Event type, time, severity and user details support searches and alerts.

The dispatcher sends one event to several handlers. Syslog, CEF and LEEF support UDP, TCP and TLS. CodeGraph records recent attempts and a healthy or degraded state for each handler.

Choose a format and transport

Choose a format and transport
Format Settings Purpose
Syslog host, port, protocol, facility, app_name RFC 5424 event transport.
CEF host, port, protocol, device_vendor, device_product, device_version Common Event Format receiver.
LEEF host, port, protocol, product_vendor, product_name, product_version Log Event Extended Format receiver.

Agree on the address, port, format and indexing rules with the SOC. For TLS, use a DNS name that matches the receiver certificate. The sender validates the server name and certificate chain against the default trust store.

Configure delivery

Settings live under security.siem in config.yaml. Set the SOC receiver address and port in your deployment. The following example uses a local TCP receiver at 127.0.0.1:15140, Syslog and the LOCAL0 facility (16).

Save this example as config.yaml in a separate check directory. Use a Python environment with the CodeGraph source package installed.

security:
  enabled: true
  siem:
    enabled: true
    syslog:
      enabled: true
      protocol: tcp
      host: 127.0.0.1
      port: 15140
      facility: 16
      app_name: codegraph
    cef:
      enabled: false
    leef:
      enabled: false
    buffer:
      max_size: 10000
      flush_interval_seconds: 5
      retry_attempts: 3
      retry_backoff_seconds: 2.0

Select handlers with enabled. To send both formats, configure both receivers. The dispatcher records each handler result.

Verify sending and receipt

This example sends one synthetic security.alert event over the real TCP transport. The receiver prints the Syslog line. The sender prints the result and request_id.

  1. Save this code as receive_siem_test.py in the check directory.
"""Receive one local TCP Syslog message for the SIEM transport check."""
import socket

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server:
    server.bind(("127.0.0.1", 15140))
    server.listen(1)
    server.settimeout(30)
    print("Listening on 127.0.0.1:15140", flush=True)
    connection, _ = server.accept()
    with connection, connection.makefile("r", encoding="utf-8") as stream:
        print(stream.readline().rstrip(), flush=True)
  1. Save the sender as send_siem_test.py in the same directory.
"""Send a synthetic security event using the selected SIEM configuration."""
import json
from uuid import uuid4

from src.security.config import SecurityConfigSource, load_security_config
from src.security.siem.base_handler import SecurityEvent, SecurityEventType
from src.security.siem.dispatcher import SIEMDispatcher

config = load_security_config(SecurityConfigSource(path="config.yaml"))
event = SecurityEvent.create(
    event_type=SecurityEventType.SECURITY_ALERT,
    message="SIEM integration test event",
    request_id=str(uuid4()),
    severity=6,
    details={"source": "documentation-check", "test": True},
)
with SIEMDispatcher(config.siem) as dispatcher:
    results = dispatcher.dispatch_sync_detailed(event)
    print(json.dumps({"request_id": event.request_id, "handlers": results}))
    succeeded = bool(results) and all(item["dispatched"] for item in results)
raise SystemExit(0 if succeeded else 1)
  1. Start the receiver in the first terminal:
python receive_siem_test.py

Wait for Listening on 127.0.0.1:15140.

  1. Send the event from the same directory in the second terminal:
python send_siem_test.py

The sender exits with code 0. Find dispatched: true in the handlers array. The receiver line contains event_type="security.alert", the message SIEM integration test event and the same request_id as the sender JSON. The receiver exits after printing one line.

  1. Run the sender again after the receiver exits. It exits with code 1; the handler returns dispatched: false and an error_summary. This checks diagnostics for an unavailable TCP receiver.

For the SOC connection, set its address and port in the deployment configuration. Find the event by request_id in the SIEM index. Check its time, type and severity. For UDP, the receiver record confirms receipt. For TCP/TLS, it also shows indexing after the network send.

How buffering works

dispatch(event) enqueues the event in process memory. A background thread sends pending events at flush_interval_seconds intervals. Failed sends are retried according to retry_attempts and retry_backoff_seconds.

The queue holds max_size events. When full, a new event replaces the oldest one and increments dropped. A process restart creates a new queue. Use these properties to choose queue capacity and plan updates.

dispatch_sync(event) sends immediately and returns success when at least one handler sends the event. dispatch_sync_detailed(event) returns each handler result. flush() starts sending queued events.

How buffering works
Counter Meaning Operator action
enqueued Events added to the queue. Compare with the event rate.
sent Successful sends from the queue. Check receipt in SIEM.
failed Failed send attempts. Check the address, transport and receiver.
retried Retry attempts. Identify the cause of unstable delivery.
dropped Lost events. Configure an alert and investigate the loss window.

Operate the integration

Alert the SOC on degraded state, queue growth, repeated retries and dropped events. Set thresholds from the measured event rate and permitted ingestion delay. Agree on sensitive-field handling, retention and access to the SIEM index.

After a delivery failure, preserve error_summary, time and the configuration without secrets. Check DNS, network, TLS and receiver health. Once delivery is restored, flush the queue and reconcile its counters with SIEM events. Record the owner, additional monitoring channel and recovery exit condition for the degradation window.

For acceptance, retain the configuration, synthetic event and failure results, queue statistics, SIEM index record and alert settings. Exercise authentication and DLP event producers through their user actions: OAuth/LDAP and DLP.

Fields and implementation

An event contains event_type, timestamp, request_id, message and severity. Optional fields describe the user, network, provider, model and DLP action. The severity values use the Syslog 0–7 scale.

Event types and fields are defined in src/security/siem/base_handler.py. The dispatcher and queue are implemented in dispatcher.py and buffer.py in the same directory. src.security.config loads typed settings from security.siem.
