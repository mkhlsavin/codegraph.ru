Refactoring Analysis Guide¶

This guide covers using the refactoring analysis module to detect code smells, analyze impact, and plan refactoring tasks.

Overview¶

The refactoring module (src/refactoring/) provides four specialized agents:

  1. TechnicalDebtDetector – Detects code smells using a pattern library
  2. DeadCodeDetector – Specialized agent for dead code detection (13 patterns + WCC)
  3. ImpactAnalyzer – Analyzes change impact and dependencies
  4. RefactoringPlanner – Creates prioritized refactoring plans and reports

All agents except RefactoringPlanner accept an optional CPGQueryService and support the context manager protocol for automatic resource management.

Quick Start¶

from src.refactoring import (
    TechnicalDebtDetector,
    DeadCodeDetector,
    ImpactAnalyzer,
    RefactoringPlanner,
)

# Step 1: Detect code smells (context manager auto-creates CPGQueryService)
with TechnicalDebtDetector() as detector:
    findings = detector.detect_all_smells(limit_per_pattern=30)

# Step 2: Analyze impact for all findings
with ImpactAnalyzer() as analyzer:
    impact_analyses = analyzer.analyze_bulk_impact(findings, limit=20)

# Step 3: Create prioritized refactoring plan
planner = RefactoringPlanner()
tasks = planner.create_refactoring_plan(findings, impact_analyses)

# Step 4: Generate report
report = planner.generate_report(findings, impact_analyses, tasks)
print(report.summary)
print(f"Total smells: {report.total_smells}")
print(f"Effort: {report.total_effort_hours:.1f}h")
for rec in report.recommendations:
    print(f"  - {rec}")

You can also pass an existing CPGQueryService to agents that accept it:

from src.services.cpg import CPGQueryService

cpg_service = CPGQueryService()
detector = TechnicalDebtDetector(cpg_service)
analyzer = ImpactAnalyzer(cpg_service)

Code Smell Detection¶

Supported Pattern Categories¶

Categories are defined in the CodeSmellCategory enum (src/refactoring/_base.py):

Category Enum Value Description Examples
Bloaters CodeSmellCategory.BLOATERS Large methods, long parameter lists God Method, Long Parameter List
OO Abusers CodeSmellCategory.OO_ABUSERS Misuse of OO features Switch Statements, Refused Bequest
Change Preventers CodeSmellCategory.CHANGE_PREVENTERS Patterns that hinder changes Divergent Change, Shotgun Surgery
Dispensables CodeSmellCategory.DISPENSABLES Dead code, speculative generality Dead Code, Speculative Generality
Couplers CodeSmellCategory.COUPLERS Excessive coupling Feature Envy, Inappropriate Intimacy
Complexity CodeSmellCategory.COMPLEXITY High cyclomatic complexity Deep Nesting, Complex Conditionals
Documentation CodeSmellCategory.DOCUMENTATION Missing or outdated docs Missing Comments, Stale Docs

Severity Levels¶

Defined in the CodeSmellSeverity enum:

Severity Enum Value Description Action
Critical CodeSmellSeverity.CRITICAL Severely impacts maintainability Fix immediately
High CodeSmellSeverity.HIGH Major maintainability issues Fix in current sprint
Medium CodeSmellSeverity.MEDIUM Moderate technical debt Plan for next sprint
Low CodeSmellSeverity.LOW Minor issue Address when convenient
Info CodeSmellSeverity.INFO Informational only Consider for improvement

Detection Methods¶

Detect all patterns:

with TechnicalDebtDetector() as detector:
    findings = detector.detect_all_smells(limit_per_pattern=30)

    for finding in findings:
        print(f"{finding.severity}: {finding.pattern_name}")
        print(f"  Location: {finding.filename}:{finding.line_number}")
        print(f"  Fix: {finding.refactoring_technique}")

detect_all_smells() iterates over all patterns in REFACTORING_PATTERNS, executes each pattern’s CPGQL query, and returns findings sorted by severity (critical first).

Detect a single pattern:

from src.refactoring import REFACTORING_PATTERNS

with TechnicalDebtDetector() as detector:
    pattern = REFACTORING_PATTERNS["GOD_METHOD"]
    findings = detector.detect_pattern(pattern, limit=30)

Detect by category:

from src.refactoring import CodeSmellCategory

with TechnicalDebtDetector() as detector:
    bloaters = detector.detect_by_category(CodeSmellCategory.BLOATERS, limit=50)
    complexity = detector.detect_by_category(CodeSmellCategory.COMPLEXITY, limit=50)

Note: detect_by_category() requires a CodeSmellCategory enum value, not a string.

Debt Metrics¶

calculate_debt_metrics() computes aggregate statistics from findings:

with TechnicalDebtDetector() as detector:
    findings = detector.detect_all_smells()
    metrics = detector.calculate_debt_metrics(findings)

    print(f"Total smells: {metrics['total_smells']}")
    print(f"Total effort: {metrics['total_effort_hours']:.1f}h")
    print(f"Debt ratio: {metrics['debt_ratio']:.2%}")
    print(f"By severity: {metrics['by_severity']}")
    print(f"By category: {metrics['by_category']}")
    print(f"Avg effort/smell: {metrics['avg_effort_per_smell']:.1f}h")

Returns a dict with keys: total_smells, total_effort_hours, by_severity, by_category, debt_ratio, avg_effort_per_smell.

@dataclass
class CodeSmellFinding:

    pattern_name: str
    category: str
    severity: str
    method_id: int

Dead Code Detection¶

DeadCodeDetector is a specialized agent for dead code detection. It runs 13 detection patterns plus Weakly Connected Components (WCC) analysis to find orphan components.

Detection Patterns¶

Pattern ID Name Detection Type Confidence
DEAD_CODE Uncalled Functions uncalled 0.70
DEPRECATED_MARKER Deprecated Markers deprecated 0.95
DISABLED_CODE_BLOCK Disabled Code (#if 0) disabled 0.99
UNUSED_VARIABLE Unused Variables unknown 0.50
EMPTY_STUB Empty Stubs stub 0.60
ERROR_ONLY_FUNCTION Error-Only Functions error_only 0.50
UNREACHABLE_AFTER_RETURN Unreachable After Return unreachable 0.90
DEAD_ASSIGNMENT Dead Assignments unknown 0.50
INVARIANT_DEAD_CODE Invariant Dead Code unknown 0.50
DEAD_CALLBACK Dead Callbacks unknown 0.50
SINGLE_CALLER_FUNCTION Single-Caller Functions unknown 0.50
TEST_ONLY_FUNCTION Test-Only Functions unknown 0.50
ORPHAN_COMPONENT Orphan Components (WCC) orphan 0.80

Dead Code Detection Methods¶

Detect all dead code:

with DeadCodeDetector() as detector:
    findings = detector.detect_all(limit_per_pattern=50)

    for finding in findings:
        print(f"[{finding.severity}] {finding.method_name}")
        print(f"  Type: {finding.detection_type}")
        print(f"  Confidence: {finding.confidence:.0%}")
        print(f"  Reason: {finding.reason}")
        print(f"  File: {finding.filename}:{finding.line_number}")

Detect specific patterns:

with DeadCodeDetector() as detector:
    findings = detector.detect_patterns(
        pattern_names=["DEAD_CODE", "DEPRECATED_MARKER", "EMPTY_STUB"],
        limit_per_pattern=30
    )

Detect by type:

with DeadCodeDetector() as detector:
    # Supported types: uncalled, deprecated, disabled, stub, error_only, unreachable, orphan
    uncalled = detector.detect_by_type("uncalled", limit=50)

Get summary statistics:

with DeadCodeDetector() as detector:
    findings = detector.detect_all()
    summary = detector.get_summary(findings)

    print(f"Total findings: {summary['total_findings']}")
    print(f"Total dead lines: {summary['total_lines']}")
    print(f"Avg confidence: {summary['avg_confidence']:.0%}")
    print(f"By type: {summary['by_type']}")
    print(f"By severity: {summary['by_severity']}")
    print(f"By file: {summary['by_file']}")

WCC Orphan Analysis¶

The detect_all() method automatically runs WCC (Weakly Connected Components) analysis in addition to pattern-based detection. WCC analysis uses a recursive CTE on the call_containment table to identify methods not reachable from any entry point (e.g., main, *_handler, *_hook, *_init).

Orphan findings have detection_type="orphan", pattern_id="DEAD_CODE_WCC", and confidence=0.8.

Dead Code Finding Structure¶

@dataclass
class DeadCodeFinding:
    finding_id: str
    pattern_id: str
    pattern_name: str
    detection_type: str   # 'uncalled', 'deprecated', 'disabled', 'orphan', etc.
    severity: str
    method_id: int
    method_name: str
    filename: str
    line_number: int
    line_count: int
    code_snippet: str
    reason: str
    confidence: float     # 0.0 to 1.0
    metadata: Dict[str, Any] = field(default_factory=dict)

Impact Analysis¶

Analyzing Method Changes¶

with ImpactAnalyzer() as analyzer:
    impact = analyzer.analyze_method_impact(
        method_name="heap_insert",
        filename="backend/access/heap/heapam.c"
    )

    print(f"Risk Level: {impact.risk_level}")
    print(f"Impact Score: {impact.impact_score:.2f}")
    print(f"Directly Affected: {len(impact.direct_dependents)} methods")
    print(f"Indirectly Affected: {len(impact.indirect_dependents)} methods")
    print(f"Files to Test: {len(impact.affected_files)}")
    print(f"Estimated Test Effort: {impact.estimated_test_effort:.1f}h")

Impact scoring: - impact_score = min(direct_count * 0.1 + indirect_count * 0.05, 1.0) - Risk levels: high (score > 0.7 or > 20 direct), medium (score > 0.4 or > 10 direct), low (otherwise)

Bulk Impact Analysis¶

analyze_bulk_impact() runs analyze_method_impact() for each finding:

with ImpactAnalyzer() as analyzer:
    impact_analyses = analyzer.analyze_bulk_impact(findings, limit=20)

    for ia in impact_analyses:
        print(f"{ia.target_method}: risk={ia.risk_level}, score={ia.impact_score:.2f}")

Impact Analysis Structure¶

@dataclass
class ImpactAnalysis:
    analysis_id: str
    target_method: str
    target_file: str
    direct_dependents: List[str]    # Methods that call target
    indirect_dependents: List[str]  # Transitive callers
    affected_files: List[str]       # Files needing review
    impact_score: float             # 0.0 to 1.0
    risk_level: str                 # "low", "medium", "high"
    estimated_test_effort: float    # Hours

Dependency Analysis¶

with ImpactAnalyzer() as analyzer:
    deps = analyzer.find_dependencies("heap_insert", depth=2)

    for dep in deps:
        print(f"{dep.from_method} -> {dep.to_method}")
        print(f"  Type: {dep.dependency_type}")
        print(f"  Strength: {dep.strength}")

find_dependencies() queries the call_containment table to find both callers and callees of the given method.

DependencyInfo Structure¶

@dataclass
class DependencyInfo:
    dependency_id: str
    from_method: str
    from_file: str
    to_method: str
    to_file: str
    dependency_type: str  # "calls", "includes", "data"
    strength: str         # "strong", "medium", "weak"

Refactoring Planning¶

RefactoringPlanner takes no constructor arguments. It operates on findings and impact analyses produced by the other agents.

Creating a Refactoring Plan¶

planner = RefactoringPlanner()

# create_refactoring_plan() returns List[RefactoringTask] directly
tasks = planner.create_refactoring_plan(findings, impact_analyses)

for task in tasks:
    print(f"\nTask {task.task_id}: {task.pattern_name}")
    print(f"  Target: {task.target_file}:{task.target_method}")
    print(f"  Priority: {task.priority}/10")
    print(f"  Effort: {task.effort_hours}h")
    print(f"  Value: {task.estimated_value:.1f}")
    print(f"  Impact: {task.impact_score:.2f}")
    print(f"  Steps:")
    for step in task.refactoring_steps:
        print(f"    - {step}")

Task Prioritization¶

Tasks are sorted by priority (highest first), then by ROI (value / effort). Priority is calculated based on:

  1. Severity – Base score from severity level (critical=10, high=7, medium=4, low=2, info=1)
  2. Impact risk – Low risk adjusts priority +1, high risk adjusts -1
  3. Category bonus – Bloaters get +2 priority (they affect many other smells)

Refactoring Task Structure¶

@dataclass
class RefactoringTask:
    task_id: str
    finding_id: str
    pattern_name: str
    target_method: str
    target_file: str
    priority: int              # 1-10, higher = more urgent
    effort_hours: float
    impact_score: float
    refactoring_steps: List[str]
    dependencies: List[str]    # Other tasks that should be done first
    estimated_value: float     # Benefit of completing this task

Refactoring Report¶

Generating a Full Report¶

generate_report() requires three positional arguments: findings, impact analyses, and tasks.

planner = RefactoringPlanner()
tasks = planner.create_refactoring_plan(findings, impact_analyses)
report = planner.generate_report(findings, impact_analyses, tasks)

print(report.summary)
print(f"Total smells: {report.total_smells}")
print(f"By severity: {report.by_severity}")
print(f"By category: {report.by_category}")
print(f"Effort: {report.total_effort_hours:.1f}h")
print(f"Estimated value: {report.estimated_value:.1f}")
for rec in report.recommendations:
    print(f"  - {rec}")

Report Structure¶

@dataclass
class RefactoringReport:
    report_id: str
    timestamp: str                          # ISO format string
    total_smells: int
    by_severity: Dict[str, int]             # e.g. {"critical": 2, "high": 5}
    by_category: Dict[str, int]             # e.g. {"bloaters": 3, "complexity": 4}
    findings: List[CodeSmellFinding]
    impact_analyses: List[ImpactAnalysis]
    tasks: List[RefactoringTask]
    total_effort_hours: float
    estimated_value: float
    summary: str                            # Executive summary text
    recommendations: List[str]              # Prioritized recommendations

Supported Patterns¶

Bloaters Patterns¶

Pattern Detection Technique
God Method Lines > 200, Complexity > 20 Extract Method
Long Parameter List Params > 5 Introduce Parameter Object
Large Class Methods > 30 Extract Class
Data Clumps Repeated param groups Extract Class

Complexity Patterns¶

Pattern Detection Technique
Complex Conditionals Nested depth > 4 Decompose Conditional
Deep Nesting Nesting depth > 5 Extract Method, Guard Clauses

Dispensables Patterns¶

Pattern Detection Technique
Dead Code Uncalled methods Remove Method
Speculative Generality Unused abstractions Remove Abstraction

OO Abusers Patterns¶

Pattern Detection Technique
Switch Statements Switch size > 5 cases Replace with Polymorphism
Refused Bequest Unused inherited methods Replace Inheritance with Delegation

Change Preventers Patterns¶

Pattern Detection Technique
Divergent Change Many reasons to change one class Extract Class
Shotgun Surgery One change affects many files Move Method, Inline Class

Couplers Patterns¶

Pattern Detection Technique
Feature Envy High coupling to other classes Move Method
Inappropriate Intimacy Excessive access to other class internals Move Method, Hide Delegate

Documentation Patterns¶

Pattern Detection Technique
Missing Comments Public methods without docstrings Add Documentation
Stale Docs Outdated comments Update or Remove

SQL Queries for Detection¶

The module uses SQL queries against the CPG (Code Property Graph) to detect patterns. Each RefactoringPattern has a cpgql_query field containing the detection SQL.

Long Methods (Bloaters):

SELECT m.name, m.full_name, m.filename, m.line_number,
       (m.line_number_end - m.line_number) AS lines
FROM nodes_method m
WHERE (m.line_number_end - m.line_number) > 200
  AND m.is_external = false
ORDER BY lines DESC;

High Complexity:

SELECT m.name, m.filename, COUNT(cs.id) AS complexity
FROM nodes_method m
JOIN edges_ast a ON m.id = a.src
JOIN nodes_control_structure cs ON a.dst = cs.id
WHERE cs.control_structure_type IN ('IF', 'WHILE', 'FOR', 'SWITCH')
GROUP BY m.id, m.name, m.filename
HAVING COUNT(cs.id) > 15
ORDER BY complexity DESC;

Uncalled Methods (Dead Code):

SELECT m.name, m.full_name, m.filename
FROM nodes_method m
WHERE m.is_external = false
  AND NOT EXISTS (
      SELECT 1 FROM edges_call ec WHERE ec.dst = m.id
  )
  AND m.name NOT LIKE 'test%'
  AND m.name NOT IN ('main', 'init');

WCC Orphan Detection (uses call_containment with recursive CTE):

WITH RECURSIVE reachable(name, id, filename, line_number, line_count, depth) AS (
    SELECT DISTINCT m.name, m.id, m.filename, m.line_number,
           (m.line_number_end - m.line_number) AS line_count, 0 AS depth
    FROM nodes_method m
    WHERE m.name = 'main'
       OR m.name LIKE '%_handler'
       OR m.name LIKE '%_hook'
       OR m.name LIKE '%_init'
    LIMIT 100

    UNION

    SELECT DISTINCT m.name, m.id, m.filename, m.line_number,
           (m.line_number_end - m.line_number) AS line_count, r.depth + 1 AS depth
    FROM nodes_method m
    JOIN call_containment c ON c.callee_name = m.name
    JOIN reachable r ON c.containing_method_name = r.name
    WHERE m.name NOT LIKE 'test_%'
      AND r.depth < 2
    LIMIT 500
)
SELECT DISTINCT m.id, m.name AS method_name, m.filename, m.line_number,
       (m.line_number_end - m.line_number) AS line_count
FROM nodes_method m
WHERE m.name NOT IN (SELECT name FROM reachable)
  AND m.name NOT LIKE 'test_%'
  AND (m.line_number_end - m.line_number) > 5
ORDER BY (m.line_number_end - m.line_number) DESC
LIMIT 50;
