CodeGraph Guides

This section explains how to use CodeGraph in real work, not just how it is built.

If you only remember one idea, remember this:

  • GoCPG is the live map of the code.
  • OpenViking is the shared memory for project context.
  • PostgreSQL keeps ownership, permissions, handoff history, and knowledge state.
  • OpenCode is the main daily interface for developers, reviewers, and testers.

The Simple Mental Model¶

CodeGraph works in three layers:

  1. GoCPG answers questions about code structure, call chains, data flow, and dependencies.
  2. OpenViking stores reusable project context, session context, and curated skills.
  3. PostgreSQL decides who owns a session, who can reopen it, who can receive it, and whether saved knowledge is still trustworthy.

This means you can:

  • ask questions about live code;
  • keep a working session across pauses;
  • hand a session from a developer to a reviewer or tester;
  • filter out stale knowledge before it misleads the model.

Main Ways to Work¶

OpenCode plugin¶

Use this when you want the smoothest daily workflow.

Typical commands:

  • /onboard
  • /review
  • /continue
  • /status
  • /update
  • /explain

Read: OpenCode Quick Start

CLI¶

Use this when you want direct control, scripting, CI jobs, or bulk operations.

Typical tasks:

  • import a project;
  • refresh project context;
  • run audits and reports;
  • inspect system state.

Read: CLI Guide

API and MCP¶

Use these when you are integrating CodeGraph into another tool or agent.

Typical tasks:

  • open or reopen a context session;
  • fetch or read project memory;
  • commit useful context back into memory;
  • inspect lifecycle state of saved knowledge.

Read:

  • Programmatic Guide

What Changed in the New Architecture¶

Older guides focused mostly on the code graph and vector search. The current model is broader:

  • sessions are explicit and reusable;
  • one session can move between people and tools inside the same project;
  • saved knowledge can be marked as current, needs_review, or deprecated;
  • retrieval can stay safe when context is stale or the memory backend is temporarily unavailable.
