Dashboard V2 Health Score Methodology

Explains how the composite Health Score is calculated, how grades are assigned, and how risk levels are determined for CISO/CTO Portfolio Dashboard V2.

Overview¶

The Health Score is a single 0–100 numeric indicator representing the overall security and quality posture of a project. It aggregates five independent components, each measuring a different quality dimension. A higher score means a healthier project.

The score feeds directly into: - Grade assignment (A through F) - Risk level classification (low / medium / high / critical) - Portfolio red-zone monitoring - Trend tracking over time

Composite Formula¶

health_score = (
    audit_component    * W_audit    +
    compliance_component * W_compliance +
    release_component  * W_release  +
    sca_component      * W_sca      +
    quality_component  * W_quality
) * 100

Where each component is a value in [0.0, 1.0] and default weights are:

Component Default Weight Field in config.yaml
Audit 0.30 weight_audit
Compliance 0.25 weight_compliance
Release 0.20 weight_release
SCA 0.15 weight_sca
Quality 0.10 weight_quality
Total 1.00 —

Weights are configurable in config.yaml under dashboard:. They must sum to exactly 1.0.

Component Details¶

Audit Component¶

Measures the result of the security audit pass (CodeGraph audit composite scenario).

audit_component = audit_score / 10.0
  • audit_score — the raw audit score on a 0–10 scale returned by the audit runner.
  • A score of 10.0 maps to audit_component = 1.0 (maximum contribution).
  • A score of 0.0 maps to audit_component = 0.0.

Compliance Component¶

Measures the percentage of GOST Р 56939 processes that pass requirements.

compliance_component = compliance_pct / 100.0
  • compliance_pct — the percentage (0–100) from the compliance checker.
  • Full coverage (100%) maps to compliance_component = 1.0.

Release Component¶

Maps the release gate status to a numeric value.

release_map = {
    "pass": 1.0,
    "warn": 0.5,
    "fail": 0.0
}
release_component = release_map[release_status]
Status Value Meaning
pass 1.0 All release gate checks passed
warn 0.5 Some checks issued warnings
fail 0.0 One or more checks failed

SCA Component¶

Measures the SCA/SBOM vulnerability burden. Critical and high vulnerabilities penalize the score more heavily than medium ones.

sca_component = max(0.0, 1.0 - (sca_critical * 0.15 + sca_high * 0.08 + sca_medium * 0.02))
Severity Penalty per finding
Critical 0.15
High 0.08
Medium 0.02

The result is clamped to [0.0, 1.0]. A project with no SCA vulnerabilities has sca_component = 1.0.

Example: 2 critical + 3 high + 5 medium = 1 - (0.30 + 0.24 + 0.10) = 0.36.

Quality Component¶

Measures code quality through four sub-dimensions, each weighted equally.

quality_component = (
    test_coverage       * 0.4 +
    doc_coverage        * 0.2 +
    (1 - dead_ratio)    * 0.2 +
    (1 - cc_normalized) * 0.2
)
Sub-dimension Weight Description
test_coverage 0.4 Unit test line coverage (0.0–1.0)
doc_coverage 0.2 Documented public functions ratio (0.0–1.0)
1 - dead_ratio 0.2 1 minus the dead code ratio (0.0–1.0)
1 - cc_normalized 0.2 1 minus normalized cyclomatic complexity (0.0–1.0)
  • dead_ratio — fraction of functions flagged as dead code.
  • cc_normalized — cyclomatic complexity normalized to [0.0, 1.0] by dividing by a configurable maximum (analysis.complexity_threshold).

Grade Thresholds¶

Health Scores map to letter grades as follows:

Grade Minimum Score Meaning
A ≥ 85 Excellent — production-ready security posture
B ≥ 70 Good — minor issues, no blockers
C ≥ 55 Fair — several issues requiring attention
D ≥ 40 Poor — significant issues present
F < 40 Critical — project must not be released

Thresholds are configurable:

dashboard:
  grade_a_min: 85.0
  grade_b_min: 70.0
  grade_c_min: 55.0
  grade_d_min: 40.0

Risk Levels¶

Risk levels combine the Health Score with specific condition overrides to give an operational classification used for alerting and red-zone monitoring.

Risk Level Condition
critical Health Score < 40 OR sca_critical > 0 OR compliance_pct < 40%
high Health Score < 55 OR release status = fail
medium Health Score < 70 OR release status = warn
low Health Score ≥ 70 AND release status = pass

Risk level takes the highest matching condition. For example, a project with score 72 but release status fail is still classified as high, not low.

Risk level thresholds are configurable:

dashboard:
  risk_critical_max_score: 40.0  # score ceiling for "critical"
  risk_high_max_score: 55.0      # score ceiling for "high"
  risk_medium_max_score: 70.0    # score ceiling for "medium"

Example Calculations¶

Example 1: Healthy Project¶

Input Value
audit_score 9.0
compliance_pct 94%
release_status pass
sca_critical 0, sca_high
test_coverage 0.85, doc_coverage

Components:

audit_component      = 9.0 / 10.0                          = 0.900
compliance_component = 94 / 100                            = 0.940
release_component    = 1.0   (pass)
sca_component        = 1.0 - (0 + 0.08 + 0.04)            = 0.880
quality_component    = 0.85*0.4 + 0.75*0.2 + 0.95*0.2 + 0.80*0.2
                     = 0.340 + 0.150 + 0.190 + 0.160       = 0.840

Health Score:

= (0.900*0.30 + 0.940*0.25 + 1.0*0.20 + 0.880*0.15 + 0.840*0.10) * 100
= (0.270 + 0.235 + 0.200 + 0.132 + 0.084) * 100
= 0.921 * 100 = 92.1

Grade: A — Risk Level: low

Example 2: Project with SCA Issues¶

Input Value
audit_score 7.5
compliance_pct 78%
release_status warn
sca_critical 2, sca_high
test_coverage 0.60, doc_coverage

Components:

audit_component      = 7.5 / 10.0                          = 0.750
compliance_component = 78 / 100                            = 0.780
release_component    = 0.5   (warn)
sca_component        = 1.0 - (0.30 + 0.40 + 0.16)         = 0.140
quality_component    = 0.60*0.4 + 0.50*0.2 + 0.90*0.2 + 0.65*0.2
                     = 0.240 + 0.100 + 0.180 + 0.130       = 0.650

Health Score:

= (0.750*0.30 + 0.780*0.25 + 0.5*0.20 + 0.140*0.15 + 0.650*0.10) * 100
= (0.225 + 0.195 + 0.100 + 0.021 + 0.065) * 100
= 0.606 * 100 = 60.6

Grade: C — Risk Level: medium (score < 70 AND release = warn)

Example 3: Red-Zone Project¶

Input Value
audit_score 4.0
compliance_pct 35%
release_status fail
sca_critical 5, sca_high
test_coverage 0.20, doc_coverage

Components:

audit_component      = 4.0 / 10.0                          = 0.400
compliance_component = 35 / 100                            = 0.350
release_component    = 0.0   (fail)
sca_component        = max(0, 1.0 - (0.75 + 0.64 + 0.24)) = max(0, -0.63) = 0.000
quality_component    = 0.20*0.4 + 0.15*0.2 + 0.60*0.2 + 0.30*0.2
                     = 0.080 + 0.030 + 0.120 + 0.060       = 0.290

Health Score:

= (0.400*0.30 + 0.350*0.25 + 0.0*0.20 + 0.0*0.15 + 0.290*0.10) * 100
= (0.120 + 0.087 + 0.000 + 0.000 + 0.029) * 100
= 0.236 * 100 = 23.6

Grade: F — Risk Level: critical (score < 40 AND compliance_pct < 40% AND sca_critical > 0)

Configuration¶

All thresholds and weights are set in config.yaml under dashboard:. See Configuration Reference for the full list of parameters.
