Dashboard Frontend Developer Guide

The CodeGraph CISO/CTO Dashboard is a single-page application built with React 18, TypeScript, Vite, Recharts, and D3. It provides a real-time operational view of code health, audit scores, compliance status, release readiness, SCA vulnerabilities, and cross-repository analysis across the entire project portfolio.

Architecture Overview¶

Technology Stack¶

Layer Technology Version
UI Library React 18.3
Language TypeScript 5.6
Build Tool Vite 6.0
Router react-router-dom 6.28
Charts Recharts 2.13
Force Graphs d3-force + d3-selection + d3-zoom 3.x
Linting ESLint 9.15
Testing Vitest 2.1

Routing¶

The application uses react-router-dom v6 with BrowserRouter:

/dashboard                -> Portfolio (index)
/dashboard/red-zone       -> RedZone
/dashboard/compare        -> CompareCenter
/dashboard/projects       -> ProjectsCatalog
/dashboard/projects/:name -> ProjectDetail
/dashboard/compliance     -> ComplianceCenter
/dashboard/cross-repo     -> CrossRepo
/dashboard/sca            -> ScaCenter
/dashboard/notifications  -> Notifications

All routes are nested under the Shell layout component, which provides the sidebar and breadcrumb.

State Management¶

The application uses two custom hooks for state management. There is no global state store; all data is fetched at the page level and passed down as props.

useApi<T> Hook¶

Location: src/hooks/useApi.ts

A generic data-fetching hook that wraps async API calls with loading state, error handling, and refetch capability.

function useApi<T>(fetcher: () => Promise<T>, deps: unknown[] = []): UseApiResult<T>

interface UseApiResult<T> {
  data: T | null;        // Response data, null until loaded
  loading: boolean;      // True during fetch
  error: string | null;  // Error message from catch, null on success
  refetch: () => void;   // Re-invoke fetcher
}

Key behaviors: - Automatically calls fetcher on mount and when deps change - Guards against state updates on unmounted components via mountedRef - Resets error to null on each new fetch

Usage example:

const { data, loading, error } = useApi(
  () => api.projectHealth("my-project", { include_sections: true }),
  [projectName]
);

useWebSocket Hook¶

Location: src/hooks/useWebSocket.ts

Manages a WebSocket connection to the Dashboard API for real-time project update notifications.

function useWebSocket(onProjectUpdated?: (name: string) => void): UseWebSocketResult

interface UseWebSocketResult {
  connected: boolean;          // Current connection status
  lastMessage: WsMessage | null; // Last received message
}

interface WsMessage {
  event: string;
  project_name?: string;
  trigger?: string;
  timestamp?: number;
  client_id?: string;
  heartbeat_seconds?: number;
  clients?: number;
}

Key behaviors: - Connects to ws[s]://<host>/api/v2/dashboard/ws using current page protocol - Auto-reconnects after 5 seconds on connection close - Calls onProjectUpdated callback when a project_updated event arrives - Silently ignores malformed messages and connection errors

API Client¶

Location: src/api/client.ts

All API calls go through the api object. Base URL: /api/v2/dashboard. Every method returns a typed Promise.

Core methods:

Method HTTP Endpoint Return Type
portfolio(params?) GET /portfolio PortfolioSummary
projectHealth(name, opts?) GET /projects/{name}/health ProjectHealthScore
trends(name, period?, metrics?) GET /projects/{name}/trends TrendsResponse
redZone(params?) GET /red-zone RedZoneResponse
compare(projects, dimensions?) GET /compare CrossProjectComparison
complianceHeatmap(standard?) GET /compliance/heatmap ComplianceHeatmapResponse
crossRepo(analysisType?) GET /cross-repo CrossRepoResponse
projectCatalog() GET /projects ProjectCatalogResponse
scaOverview(severity?) GET /sca/overview ScaPortfolioResponse (portfolio-only SCA aggregate)
projectScaSummary(name) GET /api/v1/deps/projects/{name}/summary ScaProjectSummary
projectScaDependencies(name, opts?) GET /api/v1/deps/projects/{name}/dependencies ScaProjectDependency[]
projectScaVulnerabilities(name, opts?) GET /api/v1/deps/projects/{name}/vulnerabilities ScaProjectVulnerabilityResponse
projectScaSbom(name, format) GET /api/v1/deps/projects/{name}/sbom ScaSbomDocument
exportDashboard(body) POST /export Blob

Notification methods:

Method HTTP Endpoint Return Type
notificationSubscriptions() GET /subscriptions NotificationSubscriptionResponse[]
createNotificationSubscription(body) POST /subscriptions NotificationSubscriptionResponse
updateNotificationSubscription(id, body) PATCH /subscriptions/{id} NotificationSubscriptionResponse
deleteNotificationSubscription(id) DELETE /subscriptions/{id} void
testNotificationSubscription(body) POST /subscriptions/test NotificationSubscriptionTestResponse
bootstrapNotificationRuntime(body) POST /subscriptions/bootstrap NotificationBootstrapResponse
notificationDeliveries(params?) GET /deliveries NotificationDeliveryResponse[]
notificationDeliverySummary() GET /deliveries/summary NotificationDeliverySummaryResponse
pendingNotificationDeliveries(params?) GET /deliveries/pending PendingNotificationDeliveryResponse[]
processPendingNotificationDeliveries() POST /deliveries/process-pending PendingDeliveryProcessResponse
notificationEventCatalog() GET /event-catalog NotificationEventCatalogResponse

The internal fetchJSON<T>() helper adds Content-Type: application/json and throws on non-2xx responses.

Notification runtime semantics:

  • the page is not pre-populated by default
  • notificationDeliverySummary() drives the Runtime status panel
  • live and test deliveries are intentionally split in the UI
  • bootstrapNotificationRuntime(body) is the fastest product path to the first live notification records for a real project

Portfolio runtime semantics:

  • portfolio(params) and projectCatalog(params) share the same filtered portfolio scope and period semantics
  • portfolioComparePeriods({ baseline_period, comparison_period, group_id? }) is the canonical Web path for Portfolio History
  • saved views persist current filters, compare set, baseline period, and preferred export format through savedViews(), createSavedView(...), and deleteSavedView(...)
  • portfolio alerts reuse notification contracts through createNotificationSubscription(...) with scope: "portfolio" or scope: "saved_view"
  • exportDashboard(...) carries reproducible export context through filters, compare_projects, saved_view_id, and saved_view_name

Demo fixture note:

  • frontend/scripts/capture_sales_deck_ui.mjs uses mocked notification payloads for sales-deck screenshots
  • that script is not evidence that the live notification runtime is already populated

Build Instructions¶

Prerequisites¶

  • Node.js 18+ (LTS recommended)
  • npm 9+

Development¶

cd frontend
npm install          # Install dependencies
npm run dev          # Start dev server on http://localhost:3100

The dev server proxies /api requests to http://localhost:8000 (the CodeGraph API), so the backend must be running for data to load.

Production Build¶

npm run build        # Type-check (tsc) + bundle (vite) -> dist/
npm run preview      # Preview production build locally

Output goes to frontend/dist/. The build produces three code-split chunks: - vendor – React, ReactDOM, react-router-dom - charts – Recharts - d3 – d3-force, d3-selection, d3-zoom

Source maps are enabled by default (see vite.config.ts -> build.sourcemap: true).

Lint and Type Check¶

npm run lint         # ESLint with strict rules (zero warnings allowed)
npm run typecheck    # TypeScript type check without emit

Deployment¶

Nginx Static Deployment¶

Build the application and serve the dist/ directory. All routes must fall back to index.html for client-side routing to work.

Sample Nginx configuration:

server {
    listen 80;
    server_name dashboard.example.com;

    root /var/www/codegraph-dashboard/dist;
    index index.html;

    # Client-side routing: all paths under /dashboard -> index.html
    location /dashboard {
        try_files $uri $uri/ /index.html;
    }

    # Proxy API calls to the CodeGraph backend
    location /api {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # WebSocket upgrade for real-time events
    location /api/v2/dashboard/ws {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }

    # Cache static assets
    location ~* \.(js|css|svg|png|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}

Docker Deployment¶

Sample multi-stage Dockerfile:

# Stage 1: Build
FROM node:18-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Serve
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Build and run:

docker build -t codegraph-dashboard ./frontend
docker run -p 3100:80 codegraph-dashboard

Environment Variables¶

Vite exposes environment variables prefixed with VITE_ to client code via import.meta.env.

Variable Default Description
VITE_API_URL /api (proxied in dev) Base URL for the REST API
VITE_WS_URL Auto-detected from window.location WebSocket URL for real-time events

Create a .env file in frontend/ for local overrides:

VITE_API_URL=http://localhost:8000/api
VITE_WS_URL=ws://localhost:8000/api/v2/dashboard/ws

In production, the dev proxy is not available. Configure Nginx (or another reverse proxy) to route /api to the backend, or set VITE_API_URL at build time to point to the API server directly.

How to Add a New Page¶

  1. Create the page component in src/pages/:
// src/pages/MyNewPage.tsx
import { api } from "@/api/client";
import { useApi } from "@/hooks/useApi";
import { Loading, ErrorDisplay } from "@/components/ui/StatusIndicators";

export function MyNewPage() {
  const { data, loading, error } = useApi(() => api.portfolio(), []);

  if (loading) return <Loading />;
  if (error) return <ErrorDisplay message={error} />;
  if (!data) return null;

  return (
    <div className="page-enter">
      <h1 style={{ fontSize: 22, fontWeight: 700, letterSpacing: "-0.02em" }}>
        My New Page
      </h1>
      {/* Page content */}
    </div>
  );
}
  1. Add the route in src/App.tsx:
import { MyNewPage } from "@/pages/MyNewPage";

// Inside <Routes> -> <Route element={<Shell />}>:
<Route path="my-page" element={<MyNewPage />} />
  1. Add the sidebar link in src/components/layout/Sidebar.tsx:
// Add to NAV_ITEMS array:
{ path: "/my-page", label: "My Page", icon: "grid" }
  1. Add the breadcrumb label in src/components/layout/Breadcrumb.tsx:
// Add to LABELS map:
"my-page": "My Page",
  1. Verify: open http://localhost:3100/dashboard/my-page in the browser.

How to Add a New Chart Component¶

  1. Create the chart in src/components/charts/:
// src/components/charts/MyChart.tsx
import {
  BarChart,
  Bar,
  XAxis,
  YAxis,
  CartesianGrid,
  Tooltip,
  ResponsiveContainer,
} from "recharts";

interface Props {
  data: { name: string; value: number }[];
  height?: number;
}

export function MyChart({ data, height = 280 }: Props) {
  if (data.length === 0) {
    return (
      <div style={{ textAlign: "center", color: "var(--cg-text-muted)", padding: 40, fontSize: 13 }}>
        No data available
      </div>
    );
  }

  return (
    <ResponsiveContainer width="100%" height={height}>
      <BarChart data={data} margin={{ top: 8, right: 16, bottom: 8, left: 0 }}>
        <CartesianGrid strokeDasharray="3 3" stroke="var(--cg-border)" />
        <XAxis
          dataKey="name"
          tick={{ fill: "var(--cg-text-muted)", fontSize: 10 }}
          tickLine={false}
          axisLine={{ stroke: "var(--cg-border)" }}
        />
        <YAxis
          tick={{ fill: "var(--cg-text-muted)", fontSize: 10 }}
          tickLine={false}
          axisLine={false}
          width={40}
        />
        <Tooltip
          contentStyle={{
            background: "var(--cg-surface)",
            border: "1px solid var(--cg-border)",
            borderRadius: 6,
            fontSize: 12,
            fontFamily: "var(--cg-font)",
          }}
        />
        <Bar dataKey="value" fill="var(--cg-primary)" radius={[4, 4, 0, 0]} />
      </BarChart>
    </ResponsiveContainer>
  );
}

  1. Follow these conventions: - Always wrap the chart in <ResponsiveContainer> for fluid width - Return a placeholder message when data is empty - Use CSS custom properties (var(--cg-*)) for all colors and fonts to respect the theme - Style tooltips consistently: background: var(--cg-surface), border: 1px solid var(--cg-border), borderRadius: 6, fontSize: 12 - Severity colors: critical #EF4444, high #F59E0B, medium #EAB308, low #10B981

  2. Import and use in a page component:

import { MyChart } from "@/components/charts/MyChart";

// Inside JSX:
<div className="card">
  <div className="card-header">
    <span className="card-title">My Chart Title</span>
  </div>
  <MyChart data={chartData} />
</div>

Testing¶

Unit Tests (Vitest)¶

The project uses Vitest as the test runner. Configuration inherits from vite.config.ts.

npm run test           # Run all tests once
npm run test:watch     # Run tests in watch mode

When writing tests, place them next to the source file or in a __tests__/ directory:

// src/components/ui/__tests__/StatusIndicators.test.tsx
import { render, screen } from "@testing-library/react";
import { GradeBadge } from "../StatusIndicators";

test("renders grade badge with correct label", () => {
  render(<GradeBadge grade="A" />);
  expect(screen.getByText("A")).toBeInTheDocument();
  expect(screen.getByLabelText("Grade A")).toBeInTheDocument();
});

End-to-End Tests (Playwright)¶

For E2E testing, use Playwright to verify full page flows:

npx playwright install     # Install browsers (first time)
npx playwright test        # Run E2E tests

Typical test structure:

// e2e/portfolio.spec.ts
import { test, expect } from "@playwright/test";

test("portfolio page loads and shows KPI cards", async ({ page }) => {
  await page.goto("/dashboard");
  await expect(page.locator("h1")).toContainText("Portfolio Overview");
  await expect(page.locator(".stat-value").first()).toBeVisible();
});

Theme Switching¶

The theme is controlled by the data-theme attribute on <html>:

  • On page load, main.tsx reads localStorage.getItem("cg-theme") and restores it; if absent, defaults to system preference via prefers-color-scheme
  • The ThemeToggle button in the sidebar toggles between "dark" and "light", persisting the choice to localStorage
  • Default in index.html: data-theme="dark"
